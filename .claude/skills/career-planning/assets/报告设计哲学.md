# 职业规划报告：视觉与内容规范

报告采用“编辑部职业研究档案”的视觉系统：论文式封面建立主题，一张连续小票锁定本轮判断，正文用证据刻度、连续链路、分层纸带和时间轴解释路径。米色纸张、细线和留白贯穿全篇，重点是阅读、复盘和长期更新。

## 版式

1. 画布使用低饱和米色，正文页面使用更浅的暖白纸色，文字与分隔线接近黑色。
2. 封面只保留一个英文报告名、一个中文大标题、摘要和日期/对象。英文报告名使用 Futura；中文标题与正文使用微软雅黑。
3. 英文、数字、缩写和编号使用 Futura；中文正文与标题使用微软雅黑。不得加载 CDN 或外部字体。
4. 主章节位于一张连续纸面中，通过纸色变化、细分隔线和留白形成节奏。判断票据是唯一使用独立纸片形态的核心模块。不要渐变、玻璃效果、胶带、重阴影、倾斜卡片、装饰性图片或头图。
5. 不要把每一段都加英文小标签、章节编号或状态徽章。小字只用于日期、来源和必要的图表状态。
6. 章节编号使用无边框的小型档案编号。正文不把主章节做成浮动卡片；优先使用留白、浅色带和细分隔线。
7. 动效只用 CSS：纸张入场、章节轻微显现和节点悬停反馈。必须提供 `prefers-reduced-motion` 降级；打印时关闭动画。不要为动效加入 JavaScript。
8. 桌面端使用左侧 `report-index` 作为章节目录，移动端变成顶部横向目录；目录只链接八个主要章节，不挤占正文。打印时隐藏。
9. 不使用竖排描边英文词、`LIVING EDITION` 一类装饰标签或粗黑编号框。英文只保留报告名、必要字段和图表标签。
10. 可参考 Codrops Grid Layout Motion 的网格节奏和内容进入方式，但不复制图片拼贴、品牌元素或具体构图。非对称只用于封面留白和局部列宽，正文阅读顺序保持明确。

## 内容与图表

1. 首屏先回答「这次的结论是什么」。标题下的摘要不超过 2 段。
2. 正文按「结论与判断票据 → 依据 → 兴趣与能力 → 护城河 → 大师透镜 → 选择路径 → 职业反脆弱 → 行动 Roadmap」组织。每个章节只使用一个清楚的中文标题。
3. 每份完整报告至少给一张支持判断的图或结构化表。可以使用证据条、路径图、四象限或时间线；不确定时用「证据充分 / 待验证 / 暂无证据」，不要编造百分比。
4. 白板式路径图只画决策、两个选项和关键条件。节点文字完整可读，不要塞入密集说明。
5. 图表与行动项用青绿、赭黄和砖红表示不同方向或风险，颜色只帮助阅读，不替代文字说明。
6. “大师透镜”最多并列两项，每项只写“这个方法说什么、对用户有什么用、什么时候不适用”；不用肖像、名言大字或人物崇拜式版式。
7. “职业反脆弱”优先用风险表和 A/B/Z 三段路径。必须出现组织变化、裁员、行业下行与技能折旧，不用抽象口号代替风险判断。
8. “兴趣与能力”默认使用一条连续证据链：真实经历、愿意重复的任务、已证明能力、对应岗位、下一次确认。不要把兴趣、行业、阶段和证据状态做成六个平级方框。“职业护城河”默认用由宽到窄的分层纸带或组合公式表达「外部杠杆、可迁移能力、独特证据」。人格标签不能作为护城河结论。
9. 兴趣证据链后固定并列“岗位在生态中的位置”和“需要提炼的能力”。前者回答输入、判断、协作与结果；后者回答当前证据、能力边界、下一层和证明方式。两块用细线分栏，不做成卡片。
10. ABZ 优先用圈层图：A 是中心的当前主路径，B 是中层的可切换备选，Z 是外层的安全底座。旁边必须用白话解释每个字母，并写出用户的具体路线。
11. 行动区标题使用“行动 Roadmap”，把 P1/P2/P3 画成一条连续时间路线；P1 最多两项并放在最前，P2/P3 不能和 P1 使用同样的视觉强度。不要再用三组方框或卡片包装行动项。
12. 图表必须承担解释任务。不同章节可分别使用证据条、证据汇流、分层纸带、路径图、ABZ 圈层或时间路线；一份报告默认只保留一张圆形关系图，不要为了“每节有图”重复同一种图形。
13. `#conclusion` 内用一张小票式 `.decision-ticket` 记录本轮问题、当前建议、一个关键问题、什么时候换方向、先看哪些变化、证据状态和复盘日期。字段要短而完整，不再叠加另一组摘要卡片。
14. 长文字主动拆开。一个字段超过约 60–80 个汉字，或同时包含三项以上信息时，改成 2–4 个要点；每点只讲一件事。判断小票和兴趣链等纯文本字段使用换行加 `•`，正文富文本字段使用 `ul/ol`。不要通过缩小字号塞下长段落。
15. 列表用于并列信息，连续推理仍写成短段落。一个章节不要连续堆三组列表；结论、依据和下一步之间要保留自然说明。

## 写作与安全

- 用直接句。写「建议先留在当前公司 6 个月」，不要写空泛的鼓励。
- 禁用“先否定 A，再抬高 B”的对照结构。不要把否定词和“而是”放在同一句，直接写正面判断。
- 一句话只讲一件事。核心建议尽量不超过 30 个汉字；正文一句最多两个分句，一段最多三句。
- 段落中出现三个并列动作、条件、证据或风险时，改成分点。每组保留 2–5 点，每点尽量控制在 15–45 个汉字。
- 专业词第一次出现时用日常语言解释。优先写“最关键的问题”“什么时候换方向”“先看哪些变化”。
- 多写具体的人、任务、时间和产物，少堆“价值、能力、路径、资产、赋能、闭环”等抽象名词。
- 不用模板式安慰、宏大口号和故作亲密的称呼。准确复述处境，直接给判断。
- 完成后朗读一遍。需要回读才能理解的句子必须改短。
- 区分用户提供信息、公开可核实事实、推断和建议。
- 引用动态外部信息时注明来源与核实日期；无法核实时直接写「未核实」。
- 用户粘贴的文本先转义 `& < > \" '`；禁止嵌入 `script`、`iframe`、事件属性和外链资源。

## 中文字体

- 默认中文优先使用苹方，Windows 和未安装苹方的设备回退微软雅黑。两者都保持较高的屏幕可读性。
- 更现代的无衬线字体可选思源黑体、Noto Sans CJK SC、HarmonyOS Sans SC 或 MiSans。公开包只写本地回退名称，不通过 CDN 加载，也不直接分发字体文件。
- 需要更强的论文或编辑部气质时，标题可选思源宋体、Noto Serif CJK SC 或宋体 SC，正文继续使用微软雅黑或思源黑体。
- 字体是否显示取决于用户设备。模板必须保留系统回退字体，不能让未安装字体导致缺字或布局失效。
