# 大师透镜与标杆路径

这个模块提供经过核验的外部框架，帮助用户看见原来忽略的取舍。**每份完整规划选择 1–2 个真正相关的透镜，不要为了凑名人硬套。** 不模仿名人，也不堆名言。

## 透镜准入：先验证，再使用

一个观点只有满足下面至少两项，才能称为“框架”；只满足一项时降级为“启发式”或“案例类比”：

1. **重复出现**：在同一人物的不同公开场景中反复出现，或在正式著作/课程中被明确提出。
2. **能处理新问题**：既能解释已有案例，也能推导出本案例可执行的判断。
3. **有辨识度**：避开“坚持、努力、关注用户”这类宽泛常识。

来源优先级：本人著作、正式演讲、本人访谈和官方材料 > 可靠出版物或研究 > 二手总结。用户提供完整原文时先读原文。有冲突时说明是观点随时间变化、不同场景适用不同规则，还是资料不足；不要替人物强行统一观点。

每次使用时记录：`类型（框架 / 启发式 / 案例类比）`、`来源名称或链接`、`核实状态与日期`、`适用前提`。查不到可靠来源就改用不依赖人物归属的通用决策方法，不把记忆中的名言加引号。

## 联网定向检索协议

当前宿主提供 Web Search、浏览器、网页读取或等价联网工具时，完整规划中的大师透镜默认执行公开资料检索与联网核验。检索发生在 Agent 调研阶段，与最终 HTML 的离线安全限制无关。HTML 可以记录来源标题、URL 和核实日期，但不得自动加载外部图片、脚本、字体或追踪资源。

### 查询隐私最小化

联网前先把用户材料抽象成完成核验所需的最少关键词：

- 可以使用：岗位、行业、城市或地区、职级、公开人物、公开公司、框架名、原始著作或公开事件。
- 不得使用：用户姓名、邮箱、电话、身份证号、精确住址、完整简历、私人职业档案、原始聊天记录、未公开雇主/项目/客户名称和内部数据。
- 不把整段简历、JD、offer、绩效反馈或职业档案粘贴进搜索框。只提取不指向具体个人的岗位职责、能力主题、决策问题和公开事实。
- 只有用户主动要求研究某位公开人物或公开公司，且该主体与本次判断直接相关时，才使用其公开名称。不得尝试识别匿名用户、补全其身份或抓取私人社交档案。

按下面顺序执行：

1. 根据用户的关键决策生成 2–4 个去身份化的定向查询。组合使用公开人物名、框架名、原始著作、演讲、访谈和抽象后的决策问题，不做无目标的名人检索。
2. 优先打开本人官网、著作或出版社页面、官方演讲、完整访谈、股东信、论文及机构原始档案。搜索摘要只负责发现线索，不能独立证明观点。
3. 对重要归属至少找一份一手材料；若声称观点长期稳定，再找另一个时间或场景的材料交叉验证。只有二手资料时降级为“归纳启发式”。
4. 保存来源标题、发布者、URL、发布日期或年份、访问日期，以及它支持的具体判断。区分人物原话、可靠转述和 Agent 推断。
5. 检索结果与用户处境不匹配时舍弃该透镜。最终只保留 1–2 个能改变本次取舍或行动的框架。

联网工具不可用、页面无法访问或来源不足时，明确写“本次未完成联网核验”，使用稳定的通用决策方法，并请用户提供原始材料。不要声称已穷尽公开网络，也不要用训练记忆补造链接、原话或动态履历。

## 使用底线

- 不杜撰原话、履历、融资、估值、收购数字或成功原因。
- 有联网能力时，优先核实原始著作、公开演讲、本人访谈或官方资料；引用动态事实必须附来源和核实日期。
- 无法现场核实时，只讲高置信框架，并写“框架归属未现场核实”；不要加引号伪装成原话。
- 明确区分可学习的方法与时代、资源、运气。名人的路径只提供参考。
- 不模仿名人语气。标题可以写“某某的透镜”，正文必须回到用户证据。
- 不用第一人称写“如果我是某某，我会……”，也不声称某位人物本人支持本报告的建议。

## 输出格式

每个透镜控制在 140–240 字：

```text
透镜｜人物或来源
类型与来源：框架 / 启发式 / 案例类比；来源与核实状态。
内核：这个框架真正解决什么问题。
对你意味着：结合用户证据，指出一个具体取舍或动作。
边界：哪些前提不同，不能照抄。
```

最后补一句：`把这个透镜落到本周，你应该做的是……`

## 选择矩阵

| 用户处境 | 优先透镜 | 不要误用成 |
|---|---|---|
| 跨专业、能力组合、需要聚焦 | 乔布斯：科技与人文的交叉、做减法 | “有审美就一定适合品牌” |
| 怕一步选错、需要主备方案 | 里德·霍夫曼：ABZ 职业规划 | 同时做三条主线、没有重点 |
| 有内容、作品或个人影响力 | 纳瓦尔：特定知识与杠杆；Emily Weiss：先有受众再长产品 | 粉丝数自动等于商业能力 |
| 创业、裸辞或不可逆决定 | 贝索斯：后悔最小化 | 用遥远未来逃避眼前现金流 |
| 刚毕业、方向不清 | 保罗·格雷厄姆：真实好奇心与困难问题 | 只凭兴趣忽略市场与约束 |
| 横向转岗、跨赛道 | 谢丽尔·桑德伯格：职业是攀登架 | 任何横跳都算成长 |
| 组织变化、裁员、行业波动 | 塔勒布：杠铃策略与可选项 | 把高风险选择包装成勇敢 |

## 七个核心透镜

### 1. 交叉点与做减法｜常与乔布斯相关

- **类型**：组合启发式。使用前分别核实“科技与人文交叉”及聚焦/做减法的原始材料，不把两者包装成一个正式理论。
- **内核**：差异化通常来自两类能力的交叉；真正形成辨识度还需要集中资源，决定暂时不做什么。
- **适合**：跨专业求职、内容 × 行业、审美 × 商业、技术 × 领域知识。
- **关键问题**：你身上哪两样东西叠在一起更少见？为了让它形成作品，未来半年先不投什么、不学什么？
- **边界**：跨界标签本身没有价值，必须有项目结果证明两者确实产生了业务价值。

### 2. ABZ 职业规划｜里德·霍夫曼

- **类型**：有明确出处的框架；优先核实《The Startup of You》相关章节。
- **内核**：A 是当前主路径，B 是出现更好信息时可切换的备选，Z 是最坏情况下保住现金流与生活的底线方案。
- **适合**：offer 比较、转行、裸辞、组织风险和“必须一次选对”的焦虑。
- **关键问题**：你正在全力推进的 A 是什么？什么信号会触发 B？Z 能让你撑多久？
- **边界**：B 只保留一条相邻路线，并提前投入少量时间准备。Z 必须有真实的现金、收入来源或可用资源。

### 3. 特定知识与杠杆｜常与纳瓦尔相关

- **类型**：从多次公开表达归纳的启发式；核实本人文章、播客或官方整理页，不把二手摘录当原话。
- **内核**：长期优势来自难以标准化教授、由个人经历长出来的知识；内容、产品和代码可以让一次投入被重复使用。
- **适合**：创作者、顾问、技术、个人品牌和希望减少纯工时交换的人。
- **关键问题**：你知道什么是因为你走过这段路？哪项成果离开公司后还能反复使用？
- **边界**：会发内容还不够。需要长期留下受众、作品、产品或可重复的方法。

### 4. 后悔最小化｜常与贝索斯相关

- **类型**：人物决策启发式；优先核实本人访谈或股东信相关材料。
- **内核**：把时间尺度拉长，区分短期不适和长期后悔，适合处理重要且可逆性较低的选择。
- **适合**：创业、留学、长期赛道选择和重大地域迁移。
- **关键问题**：几年后更可能后悔的是尝试失败，还是根本没有验证？
- **边界**：长期选择仍要满足现金流、家庭、健康和合同风险等现实条件。

### 5. 先有受众，再长出品牌｜Emily Weiss / Into The Gloss 与 Glossier 路径

- **类型**：公司与人物案例类比，适用范围有限。
- **内核**：持续内容可以先形成受众理解和信任，再反向发现真实需求、产品或品牌机会。
- **适合**：已有稳定内容、社群、垂类影响力或一手用户反馈的人。
- **关键问题**：受众为什么持续关注你？他们反复提出、但尚未被解决的问题是什么？
- **边界**：名人资源、融资环境和消费品牌窗口不可复制。用户可以学习“从受众反馈提炼需求”这一步。

### 6. 顺着真实好奇心做困难问题｜常与保罗·格雷厄姆相关

- **类型**：从公开文章归纳的启发式；使用前核实与本次问题直接相关的原文。
- **内核**：方向通常从两类问题中长出来：你愿意长期钻研，同时别人确实需要。
- **适合**：应届生、跨专业、方向模糊和只有“想进大厂”但没有岗位目标的人。
- **关键问题**：哪类问题即使没有作业和绩效，你仍会主动研究？你是否愿意做它枯燥的部分？
- **边界**：好奇心只是起点，必须通过项目、市场反馈和现实约束验证。

### 7. 职业是攀登架｜常与谢丽尔·桑德伯格相关

- **类型**：职业路径类比；核实正式著作或公开演讲中的原始语境。
- **内核**：职业成长不总是线性升职；一次横向移动可能补齐关键能力、业务视野或平台资源。
- **适合**：转岗、降 title 换赛道、从职能岗进入核心业务。
- **关键问题**：这次移动补的是长期画像里的哪块拼图？
- **边界**：没有能力增量的横跳只是重新开始，不能用“非线性”合理化逃避。

## 标杆路径怎么用

当用户提供某位榜样的公开履历时：画出节点，找真正拐点，拆分可复制方法与时代/资源/运气，再提炼 1–3 个用户能执行的动作。不要自动抓取私人领英数据。

用户没有具体榜样但需要职业地图时，使用常见骨架：

- **内容 / 品牌**：执行内容 → 独立负责栏目或项目 → 对增长或品牌结果负责 → 内容策略 / 品牌负责人。
- **产品**：执行需求 → 独立负责模块 → 负责产品线 → 产品负责人或新业务。
- **设计 / 创意**：执行设计 → 独立项目 → 定义视觉与策略 → 设计负责人或独立业务。
- **技术**：实现方案 → 独立模块 → 定架构与方向 → 技术负责人或创业。

路径只提供地图。最终要回答的仍然是：用户现在在哪一格，下一格需要哪项证据，这一步是否增加可迁移资产。
