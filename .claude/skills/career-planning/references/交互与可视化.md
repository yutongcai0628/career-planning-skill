# 交互与可视化（让 skill 真正区别于闲聊的两件武器）

这个文件是两套能力：**选择题题库**（把信息挖出来）和**图表模板**（把结论画出来）。它必须兼容 Claude Code、Codex、Kimi 和多数通用 Agent：有专用工具就用工具，没有就用聊天、Markdown、Mermaid 或 SVG 降级。

---

## 一、选择题挖掘：工具优先，聊天兜底

为什么是选择题：迷茫的人**回忆不出**自己擅长什么，但**认得出**——给好选项，他一眼就知道哪个像自己。所以默认用选择题，而不是开放式追问。

用法要点：
- **先探测能力**：如果当前 Agent 有互动选择题/表单工具（如 AskUserQuestion、request_user_input 或类似能力），优先用工具；如果没有，就在聊天里给编号选项，让用户回复序号、多个序号或"其他：..."。
- **工具常见限制：一次最多 4 题，每题最多 4 个选项。** 下面题库里选项多于 4 个的（如题库 B 有 10 项），必须处理：要么**合并成 4 组大类**，要么**拆成两轮问**（先问一轮，根据回答再问下一轮）。宁可分轮多问一次，也不要硬塞。
- 一次弹 **2–4 题**，分批问，别想一次问完所有维度。
- 该多选就多选（`multiSelect: true`）——兴趣/能力往往不止一个。
- 每题都给"为什么问"的语气，让用户觉得问到了点上。
- 用户永远可以选"其他"补充，所以选项不必穷举，覆盖主流即可。
- 选完之后**一定要把选择翻译成洞察**反馈给用户（"你选了 A+C，这两样叠在一起其实是……"），而不是收集完就走。

聊天兜底格式示例：

```markdown
我先问 3 个会明显影响判断的问题，直接回序号即可，也可以补充"其他"。

1. 你现在更像哪个阶段？A 在校/应届 B 1-3 年 C 3-8 年 D 8 年以上
2. 你最想解决什么？A 找方向 B 选 offer/JD C 转行 D 抗风险
3. 你最看重什么？可多选：A 成长 B 收入 C 稳定 D 自由/影响力
```

### 题库 A：地基信息（任何场景，信息不足时先问）
可在一次互动表单里同时问下面几题；没有表单时，用上面的聊天格式问：

- **阶段**（单选）：在校/应届 · 工作 1–3 年 · 3–8 年 · 8 年以上
- **现状**（单选）：迷茫、不知道往哪走 · 在纠结一个具体选择（offer/跳槽） · 想转行换赛道 · 手里有岗位/JD 想分析
- **最看重什么**（多选）：成长空间 · 收入 · 稳定性 · 自由度/自主 · 影响力 · 工作生活平衡
- **硬约束**（多选，可选）：必须留在某城市 · 收入有底线 · 家庭/时间限制 · 暂时没有

### 题库 B：兴趣 / 能力挖掘（场景①核心，也常用于②）
这是最关键的一题。"下面哪些事，你做起来最来劲、最容易忘记时间？"（**多选**）

- 从 0 想出新点子、做没人做过的事（创造）
- 把复杂的东西讲清楚、教会别人（表达 / 传授）
- 把东西做得好看、有美感、有品味（审美 / 设计）
- 说服、影响、打动别人（影响力）
- 钻研一件事、做到极致精通（专精 / 钻研）
- 张罗一群人、把事组织起来落地（组织 / 统筹）
- 一对一帮人解决具体问题、被需要（服务 / 咨询）
- 分析数据和信息、找出规律和答案（分析）
- 谈判、搞定资源、促成交易（商业 / 搞定事情）
- 照顾细节、把事做得稳妥可靠（执行 / 品控）

紧接着问**工作方式偏好**（帮区分同一兴趣下的不同岗位，多选或单选）：
- 独立深耕 ↔ 和一群人协作
- 稳定的流程和确定性 ↔ 多变、新鲜、有挑战
- 站在台前被看见 ↔ 在幕后把事做成

### 题库 C：场景化追问（按用户已说的内容定制）
当用户给了一个笼统的兴趣（如"做自媒体""喜欢和人打交道"），用选择题把它拆细。例：

"做自媒体时，**哪个环节**最让你上瘾？"（多选）：出选题/想创意 · 写文案 · 拍摄/剪辑 · 视觉排版/美化 · 看数据琢磨涨粉 · 和粉丝评论区互动 · 商业变现/接商务

不同选择指向完全不同的路（创意策划 / 内容写作 / 视频创作 / 设计 / 增长运营 / 社区运营 / 商业化），所以这一步决定方向的精度。

## 二、图表：按环境选择载体

如果当前环境有可视化/widget 工具（如 `mcp__visualize__show_widget`），优先渲染交互或 SVG 图；如果工具有说明文档（如 `read_me`），先读最新规范。没有可视化工具时按顺序降级：

1. **Mermaid**：适合路径图、流程图、决策树。
2. **内联 SVG**：适合三圈图、雷达图、四象限、匹配度图；聊天界面不渲染也没关系，导出 HTML 时可用。
3. **Markdown 表格**：适合 offer 对比、JD 匹配度、能力审计。
4. **文字图/ASCII**：最保底，别因为不能画图就不交付图形化结构。

### SVG 通用约束（照做，否则会糊）
- 根元素：`<svg width="100%" viewBox="0 0 680 H" role="img">`，**viewBox 宽度必须是 680**（和容器 1:1），H 按内容高度 +40 缓冲。首子元素放 `<title>` 和 `<desc>`。
- 在支持主题变量的 widget 里，颜色优先用 CSS 变量，不要硬编码 `#333` 之类（深色模式会看不见）：
  - 文字：`--text-primary`（主）、`--text-secondary`（次）、`--text-muted`（提示）
  - 面：`--surface-2`（白卡）、`--surface-1`（卡）、`--bg-accent`（高亮底）、`--text-accent`（高亮字）
  - 线：`--border`
  - 分类色：`var(--series-1)`…`var(--series-6)`（给不同类目上色）
- 在独立 HTML、Markdown 或不支持 CSS 变量的平台里，改用固定色：文字 `#1b1b2b`、次要 `#5b5b6e`、边线 `#e7e7ee`、主色 `#4338ca`、成功/警告/危险 `#0f766e`/`#b45309`/`#b91c1c`。
- 字重只用 400 和 500；不要负坐标；背景透明，不要再包带背景色的 `<div>`。

### 图 1：兴趣 × 能力 × 价值 三圈图（挖掘阶段的招牌图）
三个相交的圆（兴趣 / 能力 / 价值），在交集处标出用户的"甜区"——也就是三者重叠的那个职业方向。用来直观告诉用户："你的机会在这里。"画法：三个半透明填充圆（`fill-opacity:0.25`，分别用 series-1/2/3），圆心呈三角分布、两两相交，中心三重交集写上甜区关键词。每个圆边上标注从用户选择里提炼的词（兴趣圈写他选的兴趣，能力圈写提炼的能力点，价值圈写他看重的东西）。

### 图 2：能力雷达图（给能力点打分、看长短板）
把你识别出的 4–6 个能力维度画成雷达图，每维 0–100 打分（基于用户的经历和选择，标注你的判断依据）。轴线用 `--border`，多边形填充用 `var(--series-1)` 加 `fill-opacity:0.3`，顶点标维度名（`--text-secondary`）。用来让用户一眼看到"我强在哪、弱在哪"。计算每个顶点坐标：中心 (cx,cy)，第 i 轴角度 = -90° + i×(360/n)，顶点 = (cx + r×score/100×cos, cy + r×score/100×sin)。

### 图 3：职业方向卡片（给 2–3 条候选方向）
横排 2–3 张卡片，每张：方向名（标题）、一句话"为什么适合你"、匹配的能力点标签、第一步怎么验证。最推荐的那张用 `border:2px solid var(--border-accent)` 并加"最推荐"小标签。用 HTML 卡片或 SVG 都行。这是把抽象方向变具体的关键图。

### 图 4：职业路径图（时间轴 / 阶梯）
现在 → 1 年 → 3 年 →（终局画像）的横向阶梯。每个节点写：该阶段的目标、要攒的核心能力、典型动作。用来体现"倒推"——让用户看到这一步通向哪。

### 图 5：大厂 vs 创业 对比（场景②）
两列对比卡，分别列"给你什么 / 代价 / 适合谁"，并在底部高亮"以你的情况，更该选哪个、为什么"。

### 图 6：复利 vs 折旧 四象限（场景②）
横轴"会折旧 ↔ 会复利"，纵轴"现在投入多 ↔ 少"，把用户当前/候选的几项能力或选择点上去，直观看出哪些在为未来存钱、哪些在出卖时间。

### 图 7：JD 匹配度图（场景③）
把 JD 的关键要求逐条列出，每条用一个三色状态条标注：已具备（`--text-success`）/ 可补齐（`--text-warning`）/ 硬伤缺口（`--text-danger`）。顶部给一个总体匹配定性结论。用来让"适不适合"一目了然。

## 三、一次完整咨询的节奏（把两件武器串起来）
1. 用户开口 → 判断场景 → 信息不足就**问题库 A**（+ 必要时 B/C），分批问。
2. 收齐后，把选择**翻译成洞察**讲给用户听。
3. 出**一张核心图**（挖掘→三圈/雷达；给方向→方向卡片/路径图；JD→匹配度图）。
4. 配合报告模板给判断、建议、30/90 天动作。
5. 留钩子让用户继续（"想让我就其中某条方向，帮你拆得更细吗？"）。
