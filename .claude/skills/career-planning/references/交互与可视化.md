# 交互与可视化

这个文件提供两套方法：**选择题题库**用来降低表达门槛，**图表模板**用来说明判断关系。它必须兼容 Claude Code、Codex、Kimi 和多数通用 Agent：有专用工具时使用工具，没有时用聊天、Markdown、Mermaid 或 SVG 降级。

## 目录

- 一、选择题挖掘：工具优先，聊天兜底
- 二、图表：按环境选择载体
- 三、一次完整咨询的节奏

## 一、选择题挖掘：工具优先，聊天兜底

选择题可以降低回忆负担。迷茫的人常常说不出自己擅长什么，但看到具体选项时，通常能判断哪个更像自己。默认先给选择题，再追问真实经历。

用法要点：
- **先探测能力**：只在当前模式下确实可调用时，才使用互动选择题/表单工具（如 AskUserQuestion、request_user_input 或类似能力）。调用前读取当前 schema，不根据工具名猜参数。没有工具或调用失败时，立即改用聊天编号，让用户回复序号、多个序号或“其他：...”。
- **限制由宿主决定**：Claude 的 AskUserQuestion 和 Codex 的 request_user_input 在题数、选项数、多选及可用模式上都可能不同。默认采用保守上限：一轮 1–3 题，每题 2–3 个主选项，把“其他/不确定”交给宿主自带入口或聊天补充。宿主明确支持更多选项时才扩展。
- 一次问 **1–3 题**，分批进行。题库选项较多时，先合并成 2–3 组或拆成两轮。
- 采用“提问 → 反馈一个暂定发现 → 再问下一组”的节奏。每轮都让用户看到当前判断怎样变化，不连续发十几道题，也不等问卷全部结束才给反馈。
- 需要多选时，先确认工具是否支持。不支持时用单选做第一轮缩小范围，或让用户在聊天中回复多个编号；不写死 `multiSelect` 等某一宿主专属参数。
- 每题都给"为什么问"的语气，让用户觉得问到了点上。
- 用户永远可以选"其他"补充，所以选项不必穷举，覆盖主流即可。
- 选完之后**一定要把选择翻译成洞察**反馈给用户，例如：“你选了 A+C，这两个答案共同指向……”

聊天兜底格式示例：

```markdown
我先问 3 个会明显影响判断的问题，直接回序号即可，也可以补充"其他"。

1. 你现在更像哪个阶段？A 在校/应届 B 1-3 年 C 3-8 年 D 8 年以上
2. 你最想解决什么？A 找方向 B 选 offer/JD C 转行 D 抗风险
3. 你最看重什么？可多选：A 成长 B 收入 C 稳定 D 自由/影响力
```

### 题库 A：地基信息（任何场景，信息不足时先问）
可在一次互动表单里同时问下面几题；没有表单时，用上面的聊天格式问：

- **阶段**（单选）：在校/应届 · 工作 1–3 年 · 3–8 年 · 8 年以上
- **现状**（单选）：迷茫、不知道往哪走 · 在纠结一个具体选择（offer/跳槽） · 想转行换赛道 · 手里有岗位/JD 想分析
- **最看重什么**（多选）：成长空间 · 收入 · 稳定性 · 自由度/自主 · 影响力 · 工作生活平衡
- **硬约束**（多选，可选）：必须留在某城市 · 收入有底线 · 家庭/时间限制 · 暂时没有

### 题库 B：兴趣 / 能力挖掘（场景①核心，也常用于②）
这是关键问题。“下面哪些事，你更愿意持续投入，也较容易保持专注？”（**多选**）

- 从 0 想出新点子、做没人做过的事（创造）
- 把复杂的东西讲清楚、教会别人（表达 / 传授）
- 把东西做得好看、有美感、有品味（审美 / 设计）
- 说服、影响、打动别人（影响力）
- 钻研一件事、做到极致精通（专精 / 钻研）
- 张罗一群人、把事组织起来落地（组织 / 统筹）
- 一对一帮人解决具体问题、被需要（服务 / 咨询）
- 分析数据和信息、找出规律和答案（分析）
- 谈判、协调资源、促成交易（商业 / 资源协调）
- 照顾细节、把事做得稳妥可靠（执行 / 品控）

紧接着问**工作方式偏好**（帮区分同一兴趣下的不同岗位，多选或单选）：
- 独立深耕 ↔ 和一群人协作
- 稳定的流程和确定性 ↔ 多变、新鲜、有挑战
- 站在台前被看见 ↔ 在幕后把事做成

### 题库 C：场景化追问（按用户已说的内容定制）
当用户给了一个笼统的兴趣（如"做自媒体""喜欢和人打交道"），用选择题把它拆细。例：

“做自媒体时，**哪个环节**你最愿意持续做？”（多选）：出选题/想创意 · 写文案 · 拍摄/剪辑 · 视觉排版/美化 · 看数据分析内容表现 · 和粉丝评论区互动 · 商业变现/接商务

不同选择指向完全不同的路（创意策划 / 内容写作 / 视频创作 / 设计 / 增长运营 / 社区运营 / 商业化），所以这一步决定方向的精度。

### 题库 D：护城河证据（所有完整规划）

分两轮选择最关键的 2–4 题，不要求用户一次答完：

- **别人为什么找你**：想法/判断 · 专业知识 · 资源关系 · 可靠落地 · 表达审美 · 暂时不确定。
- **哪类结果重复出现**：增长或转化 · 复杂问题被理清 · 项目被推进 · 作品受到认可 · 客户/同事持续复用 · 尚无明确结果。
- **离开公司还能带走什么**：作品案例 · 方法与领域认知 · 受众/个人账号 · 行业关系与口碑 · 可独立交付的服务 · 暂时没有。
- **最难被复制的是哪种组合**：让用户多选 2–3 项，再追问一个具体案例；单项通用能力不直接称为护城河。

## 二、图表：按环境选择载体

如果当前环境有可视化/widget 工具（如 `mcp__visualize__show_widget`），优先渲染交互或 SVG 图；如果工具有说明文档（如 `read_me`），先读最新规范。没有可视化工具时按顺序降级：

1. **Mermaid**：适合路径图、流程图、决策树。
2. **内联 SVG**：适合四象限、路径关系和匹配度图；聊天界面不渲染也没关系，导出 HTML 时可用。
3. **Markdown 表格**：适合 offer 对比、JD 匹配度、能力审计。
4. **文字图/ASCII**：最后的降级方式。无法画图时，仍要交付可读的关系结构。

### SVG 通用约束（照做，否则会糊）
- 根元素：`<svg width="100%" viewBox="0 0 680 H" role="img">`，**viewBox 宽度必须是 680**（和容器 1:1），H 按内容高度 +40 缓冲。首子元素放 `<title>` 和 `<desc>`。
- 在支持主题变量的 widget 里，颜色优先用 CSS 变量，不要硬编码 `#333` 之类（深色模式会看不见）：
  - 文字：`--text-primary`（主）、`--text-secondary`（次）、`--text-muted`（提示）
  - 面：`--surface-2`（白卡）、`--surface-1`（卡）、`--bg-accent`（高亮底）、`--text-accent`（高亮字）
  - 线：`--border`
  - 分类色：`var(--series-1)`…`var(--series-6)`（给不同类目上色）
- 在职业档案 HTML 中沿用 `assets/报告模板.html` 的纸本配色：文字 `#1f211e`、次要文字 `#68675f`、纸张 `#f8f3e9`，方向/待验证/风险使用 `#245947` / `#b7832d` / `#aa5942`。其他不支持 CSS 变量的平台也优先使用这组固定色，避免报告风格漂移。
- 字重只用 400、500 和 600；不要负坐标；SVG 背景透明，不要再包带背景色的 `<div>`。

### 图 1：兴趣到岗位的证据链

按顺序连接五步：`真实经历 → 愿意重复的任务 → 已经证明的能力 → 对应岗位 → 下一次确认`。每一步只写一个判断和一条证据。读者应能沿着线从经历走到建议。HTML 使用模板中的 `.interest-path`，不要把兴趣、行业、阶段、已确认和待验证做成多组平级方框。

“已确认 / 待验证 / 已排除”可以写在对应步骤的文字里，也可以放在结尾的一张简短检查清单中。状态用于说明证据强弱，不能替代推理顺序。

### 图 2：能力证据图（看已证明与待验证）
列出 4–6 个能力维度，并按「证据充分 / 有部分证据 / 待验证」分级；每一项旁边写一条行为或结果依据。优先使用横向证据条或矩阵，不默认给 0–100 分，也不把“没提供案例”写成“能力弱”。只有用户提供了明确量表或可比数据时，才使用数字刻度，并注明数据来源。

### 图 3：职业方向对照（给 2–3 条候选方向）

用一张对照表或连续纸条列出：方向名、三项日常任务、匹配依据、主要缺口和 14 天验证。主方向用浅底色或左侧细线强调，不使用粗描边卡片。职位名称和日常任务要参考 `行业与岗位地图.md`，实时需求仍需检查近期 JD。

### 图 4：职业路径图（时间轴 / 阶梯）
现在 → 1 年 → 3 年 →（未来目标）的横向阶梯。每个节点写：该阶段的目标、要积累的核心能力和典型动作。让用户看到今天这一步通向哪里。

### 图 5：大厂 vs 创业 对比（场景②）
两列对比卡，分别列"给你什么 / 代价 / 适合谁"，并在底部高亮"以你的情况，更该选哪个、为什么"。

### 图 6：复利 vs 折旧 四象限（场景②）
横轴“会折旧 ↔ 会复利”，纵轴“现在投入多 ↔ 少”，把用户当前或候选的几项能力放上去，看清哪些能留下长期积累，哪些主要换取当期收入。

### 图 7：JD 匹配度图（场景③）
把 JD 的关键要求逐条列出，每条用一个三色状态条标注：已具备（`--text-success`）/ 可补齐（`--text-warning`）/ 关键门槛（`--text-danger`）。顶部给一个总体匹配的定性结论，让用户快速看清匹配项和需要补足的部分。

### 图 8：护城河分层纸带 / 公式图

默认用由宽到窄的三层纸带表达：`外部杠杆 → 可迁移能力 → 独特证据`，提醒读者从最内层证据开始建设。需要展示更多组成项时，再使用组合链：`可重复能力 × 领域认知 × 可携带资产 × 真实需求/结果 → 护城河假设`。每一项只放一条用户证据；没有证据的项标“待验证”，最终结论写“已形成 / 雏形 / 尚未形成”。不要再使用同心圆、五边形分数或夸张面积暗示确定性。

### 图 9：判断票据

用于离职、入职、offer、转行等具体决策，固定放在 HTML 的 `#conclusion`：使用一张连续小票，依次写本轮问题、当前建议、一个关键问题、什么时候换方向、先看哪些变化、复盘日期和证据状态。前三项占整行，四个辅助字段在桌面可排成两列，手机自动回到单列。字段之间用细虚线分隔。使用 `assets/报告模板.html` 的 `.decision-ticket`，不要改回横向表格，也不要再叠加加权分数卡。

### 图 10：岗位生态位置与能力账户

岗位生态位置按“上游输入 → 核心判断 → 协作交付 → 负责结果”表达。重点说明用户将拥有什么判断权、结果反馈和可携带积累，不用组织架构图堆岗位名称。

能力账户与它并列，每项写“当前证据 → 下一层能力 → 下一份证明”。完整规划保留 3–5 项，最后收成一句能力提炼句。HTML 使用 `.career-depth`、`.ecosystem-panel` 和 `.ability-panel`，用细线分栏，不做成两张卡片。

### HTML 组件选择

- 兴趣：复制模板中的 `.interest-path`，五个步骤必须按顺序连接并能独立换行。
- 岗位方向：复制 `.role-compare` 与 `.role-row`，依次写主方向、相邻方向和后续方向；每行包含行业、日常任务与缺口。
- 深度判断：复制 `.career-depth`；`.ecosystem-panel` 写岗位输入、判断、协作与结果，`.ability-panel` 写当前证据、下一层和证明方式。
- 护城河：复制 `.moat-layers`；手机端三层都使用 100% 宽度。
- ABZ：只有这一节默认使用 `.abz-map` 圈层图，圆内只放短标签，完整解释写在圆外。
- 行动：使用 `.action-roadmap` 连续时间路线，不使用方框套叠。

## 三、一次完整咨询的节奏（把两件武器串起来）
1. 用户开口 → 判断场景 → 信息不足就用**问题库 A**，方向迷茫时加 B/C，完整规划加 D；每轮根据宿主限制问 1–3 题。
2. 每轮回答后，把选择翻译成一个暂定发现，并说明还缺哪条行为证据。
3. 形成兴趣与能力证据，读取 `行业与岗位地图.md`，再结合人生阶段与约束给出岗位和行业方向；明确岗位生态位置并形成能力账户。
4. 出一张核心图（兴趣→岗位证据链；护城河→分层纸带/公式图；方向→路径图；JD→匹配度图）。
5. 按报告模板交付判断票据、ABZ 圈层解释和带 P1/P2/P3 阶段的行动 Roadmap，把待验证项和复盘日期留给下一轮更新。
