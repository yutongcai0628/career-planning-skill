# 导出报告（把规划交付成正式文档）

让规划不只停在对话里，而是交付成一份**能保存、能分享、看起来很专业**的文档。这是把 skill 从"聊天"提升到"咨询产品"的一步。

## 何时提出导出
给完一份完整规划后，主动问一句"要不要我帮你导出成一份正式报告？"；或用户说"生成报告/导出/存成文档/做成 PDF/写到飞书"时立即执行。

## 格式自动路由

先识别用户有没有明确要某种格式：
- 用户说"HTML / 网页 / 可打印" → 直接做 **HTML 精美报告**。
- 用户说"PDF" → 先做 HTML，再转 PDF 或指导用户打印为 PDF。
- 用户说"Markdown / md / 发我文本版" → 直接做 **Markdown**。
- 用户说"飞书 / Lark / 飞书文档 / 写到文档 / 画板" → 优先做 **飞书/Lark 文档**；如果没有飞书能力，退回 HTML/Markdown 并说明原因。
- 用户没有指定 → 用当前环境可用的选择题/表单能力让用户选格式；没有工具时直接在聊天里给 4 个编号选项：

- **HTML 精美报告**（推荐，自带样式、内嵌图表、可直接打印成 PDF）
- **PDF 报告**
- **飞书/Lark 文档**（当前环境有飞书能力才用）
- **Markdown**（朴素、通用）

不要一次全做。用户选哪种做哪种；如果用户说"都要"，先做 HTML，再按需派生 PDF / Markdown / 飞书版。

## 各格式怎么做

### 1. HTML 精美报告（默认、自包含、人人可用）
**视觉基调是「职业决策报告」**：白底、深色正文、青绿/黄/珊瑚状态色，信息层级清楚；中文用微软雅黑，英文、数字和图表标签用 Futura。HTML 内不使用图片、外链资源或脚本；用数据条、关系图、决策画板、四象限、时间线和行动清单呈现判断。动效仅用于阅读辅助，打印时必须完整展示。动手前先读 `assets/报告设计哲学.md`。

1. 读取模板 `assets/报告模板.html` 和 `assets/报告设计哲学.md`。
2. 替换 `{{NAME}}`（用档案里的名字）、`{{DATE}}`、`{{TAGLINE}}`（一句话概括这个人，如「给一个会增长、敢露脸的内容创作者」）、`{{CONTENT}}`。
3. **图表纪律（硬要求）**：数据是这份刊物的主角，纯文字报告不合格——每份至少 **1 组 `.stat-strip` 大字报 ＋ 2 个图表件**（`.bars` 条形图、`.ring` 环形占比、`.chart-card` 内联 SVG 任选其二）。能画图的判断就别用文字堆：对比用条形、占比用环形、结构与路径用 SVG。
4. **标点纪律（硬要求）**：中文语境一律全角标点（，。：；！？「」《》），中文引用必须用「」，不许用半角引号包中文；英文标签与短语一律英文标点；中英夹排时数字与英文两侧各留一个半角空格。交付前通读专查标点。
5. 把 `{{CONTENT}}` 换成规划正文，用模板结构件写：`section` ／ `.stat-strip` ／ `.bars`（`--w` 定宽，滚动到位才生长）／ `.rings`（`--p` 定百分比，缓缓转出）／ `.pullquote`（居中金句，每份 1 处）／ `.callout`（核心洞察，金色左边线）／ `details.expand`（深读抽屉，打印自动展开）／ `.insight-grid` ／ `.chart-card` ／ `.whiteboard` ／ `.matrix` ／ `.timeline` ／ `ol.actions`。动效 class：封面 `rise`＋`--d` 延迟，正文块 `reveal`。免责声明已内置页脚。
   - **HTML 安全**：用户粘贴的 JD、履历、聊天原文必须先转义 `& < > " '`；禁止 `<script>`、`iframe`、事件属性、外链资源——交互只用模板自带的 CSS 与 `<details>`，不写脚本。
6. **SVG 图表**只用模板 `:root` 固定色——古金 `#9c6f2d`、墨字 `#201f1a`、次要 `#6d675c`、细线 `#e8e3d7`、纸色 `#fcfbf7`、成功／警告／风险 `#5f7355`／`#a8823e`／`#9c4a3c`。风格：细金线、几何形，像科学期刊插图，不像营销 PPT。
7. 写到 `职业档案/报告/职业规划报告-<名字>-<日期>.html`。如果当前环境允许打开本地文件，就打开它；不允许或不是桌面环境时，把完整路径告诉用户，并说明可用浏览器打开。想要 PDF，可在浏览器打印为 PDF，模板已经为打印优化过。

### 2. PDF 报告
最稳的方式就是**先生成上面的 HTML，再转 PDF**：
- 首选让用户在打开的 HTML 页面里打印为 PDF（macOS 通常是 `Cmd+P`，Windows/Linux 通常是 `Ctrl+P`）。
- 若环境里有 Chrome/Chromium/Edge 的 headless 能力，可命令行转 PDF；路径按当前系统实际改，不要写死 macOS 路径。
- 若当前 Agent 有 PDF 生成/处理能力，也可以用它来生成 PDF。
不要硬造一个脆弱的 PDF 流程——HTML→打印 是最可靠的。

### 3. 飞书/Lark 文档（可选，当前环境有能力才用）
**先判断有没有飞书能力**：可用能力里是否有飞书/Lark 文档、云盘、导入能力，或本地是否安装并可认证 `lark-cli`。没有就告诉用户"当前环境没有飞书写入能力，我先给你 HTML/Markdown 版"，优雅跳过，别报错。
有的话：
1. 把规划正文整理成 **Markdown**。
2. 如果有 `lark-cli`，优先按当前环境已安装的飞书 CLI / skill 说明创建云文档或导入 Markdown/HTML；如果有 `lark-doc` / `lark-drive` / 飞书文档能力，也可以用它们创建文档。不要写死某个命令版本，先探测能力再执行。
3. **图表优先用飞书画板呈现**：如果当前环境有 `lark-whiteboard` skill/能力，报告里的三圈图、职业路径图、复利 vs 折旧四象限、JD 匹配度图、组织冲击/反脆弱路径图，优先调用 `lark-whiteboard` 写入画板。
   - 使用前按 `lark-whiteboard` 规则读取共享认证说明，确认 `lark-cli` 和 whiteboard CLI 可用。
   - 需要新画板时，先通过飞书文档能力在文档里插入空白 whiteboard，拿到 `board_token`，再交给 `lark-whiteboard` 更新。
   - 流程图、时间线、简单路径图优先用 Mermaid；复杂关系图、四象限、三圈图可用 SVG/DSL 路径。整体更新画板时使用覆盖式更新，避免新旧内容重叠。
   - 画板失败就退回安全内联 SVG、表格或文字结构，并标注"详见 HTML 版图表"，别因为图卡住整个流程。
4. 把生成的文档链接回给用户。

### 4. Markdown（兜底）
直接把规划正文写成 `职业档案/报告/职业规划报告-<名字>-<日期>.md`。图表用一句话描述或附 HTML 版链接。永远能用，零依赖。

## 隐私
报告含个人数据，统一存在 `职业档案/报告/` 下——该目录已被根目录 `.gitignore` 忽略，开源 push 不会泄露。

## 原则
- **内容复用**：报告正文就是你刚在对话里给的规划，别重写一版、别注水，把对话里的判断/分析/建议/行动原样结构化即可。
- **图表带上**：有图的话一定放进报告，这是"高级感"的关键。
- **一次只做一种**：用户选哪种做哪种，做完给路径/链接，别一次全导。
