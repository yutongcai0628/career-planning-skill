# HTML、PDF 与飞书交付

完整职业规划开始时先确认用户是否有飞书 CLI。只有 CLI/飞书文档能力已连接并授权、且用户选择飞书时，才改为创建或更新带主画板的飞书文档；其他情况默认写入本地 HTML。先读 `references/持续档案.md`。

## 格式路由

- **默认路由**：读取 `assets/报告模板.html` 和 `assets/报告设计哲学.md`，自动生成或更新同一个 HTML 职业档案。
- **已选择飞书/Lark**：更新同一篇结构化飞书文档；首次完整档案配置 2–3 张已填充画板，不生成 HTML；实际读写前遵循当前环境的 `lark-doc` 与 `lark-whiteboard` 说明。
- **用户说 PDF**：若主档案是 HTML，更新后通过浏览器打印或可靠的 PDF 工具转换；若主档案是飞书，先询问用户要从飞书导出还是额外生成 HTML，不擅自维护第二套档案。
- **用户明确说两种都要**：分别更新 HTML 与同一篇飞书文档，并报告两边是否成功。
- **用户明确拒绝保存或没有文件权限**：在对话中交付完整内容，不创建 Markdown 兜底文件。

## HTML 要求

1. 固定包含 `conclusion`、`evidence`、`interest-map`、`moat`、`master-lens`、`career-path`、`antifragility`、`actions`、`open-questions`、`user-notes`、`decision-history` 十一个 section id。
2. 正文按“结论与判断票据 → 证据 → 兴趣与能力 → 护城河 → 大师透镜 → 路径 → 反脆弱 → 行动 Roadmap → 后续问题”组织；`#conclusion` 内必须有 `.decision-ticket`。
3. 至少有一张支撑判断的可视化；完整规划的反脆弱部分至少有一张风险对比或 A/B/Z 路径图。
4. 大师透镜只用 1–2 个相关框架，标注框架/启发式/案例类比、来源状态、对用户的启发和类比边界；动态履历、公司数字和引语必须现场核实。
5. 不凭薄弱信息生成百分比。使用“证据充分 / 待验证 / 暂无证据”和高/中/低等离散状态。
6. 中文优先使用苹方，Windows 回退微软雅黑；英文、数字、缩写和编号使用 Futura。页面使用米色纸张与编辑部研究档案版式，封面、判断小票、证据刻度、连续链路、分层纸带和时间轴共用同一套细线与留白规则。只使用小幅 CSS 滚动动效；不放头图、图片、胶带装饰、竖排描边词、外链字体、CDN 或 JavaScript。手机与打印必须降级。
7. `interest-map` 使用“真实经历 → 愿意重复的任务 → 已证明能力 → 对应岗位 → 下一次确认”的连续证据链，并在文字中标明已确认、待验证或已排除。候选岗位用三行以内的对照表说明行业、日常任务和缺口；随后必须用 `.ecosystem-panel` 解释岗位的输入、判断、协作、结果、重要性来源与未来 3 年变化，用 `.ability-panel` 写 3–5 项“当前证据、能力边界、下一层能力、下一份证明”。`moat` 给出假设、当前层级、证据、缺口、迁移范围，以及 90 天、1 年和 3–5 年建设顺序。行动区标题使用“行动 Roadmap”，必须标 P1/P2/P3 阶段并写时间、产物和验收信号，不用方框套叠。
8. 第一次出现 ABZ 时用白话解释 A 当前主路径、B 可切换备选和 Z 安全底座，不只放三个字母；HTML 优先用 A 在中心、B 在中层、Z 在外层的圈层图。
9. 不在每段前堆英文标签、状态徽章和说明小字。图表服务于判断，正文保持自然。
10. 默认输出到当前工作区的 `职业档案/职业档案.html`，状态文件为 `职业档案/职业档案.state.json`；若用户明确指定昵称、文件名或一次性报告，再使用对应名称。
11. 生成后进行视觉检查：桌面和移动端无文字重叠或正文横向溢出，目录链接都能定位到现有 section，判断票据与图表非空，行动项可读，打印版隐藏目录并关闭阴影与实验性动效，且不截断关键模块。
12. 自动处理长文字：字段超过约 60–80 个汉字或包含三项以上并列信息时，拆成 2–4 点。普通文本字段使用 `•` 加换行，富文本字段使用 `ul/ol`；每点只写一个动作、证据、条件或结论。完整字体选择见 `assets/报告设计哲学.md`。

## 安全生成流程

当前宿主能运行 Python 时，优先使用 Skill 自带脚本。不要把用户原文直接拼接进模板。

1. 在当前工作区被忽略的 `职业档案/` 中准备 UTF-8 JSON。字段名与 `assets/报告模板.html` 的占位符一致；普通文字字段只放纯文本，需要列表、表格或图表的字段才放 HTML 片段。JSON 与 HTML 放在同一隐私目录。
2. 第一次创建时，在本 Skill 根目录运行：

```bash
python3 scripts/render_report.py \
  --data <完整档案数据.json> \
  --state <职业档案.state.json> \
  --output <职业档案.html>
python3 scripts/validate_report.py <职业档案.html>
```

3. 后续只准备变化字段。用户笔记和决策历史放在 `append` 中：

```bash
python3 scripts/render_report.py \
  --data <本次更新.json> \
  --state <职业档案.state.json> \
  --output <职业档案.html>
python3 scripts/validate_report.py <职业档案.html>
```

4. `render_report.py` 会合并状态、保护 `USER_NOTES`、追加 `DECISION_HISTORY`，转义普通文字，并只允许有限的排版与 SVG 属性。它会移除脚本、事件属性、外部资源和未知属性；模板中的 CSP 还会禁止报告自动联网。
5. 只有用户明确要求更正或删除用户笔记/历史时，才把完整替换值放入 `fields`，并增加 `--allow-protected-replace`。执行前先保留备份。
6. 生成失败时先修正缺失字段或不合规片段。不要绕过校验，也不要覆盖模板本身。
7. 宿主无法运行脚本时，复制模板后手工替换。仍需检查：占位符全部清空、11 个固定 id 各出现一次、兴趣证据链有五步、判断票据非空、没有 `script` / `iframe` / `on*` / `javascript:` / 外链资源。

所有宿主都要沿用 `assets/报告数据示例.json` 中的组件类名和嵌套关系。不要新建整页 HTML、重写全局 CSS、改变固定章节顺序，或把正文改成宿主自行设计的卡片系统。内容较少时允许留白，内容较多时优先删减、拆段和分点，不通过缩小字体解决溢出。

JSON、更新补丁和中间文件同样属于个人职业档案，不得放进公开仓库、聊天附件或 RedSkill 发布包。

## 飞书

实际读写前遵循当前环境的飞书工具说明；必须读取 `lark-shared`、`lark-doc` 与 `lark-whiteboard` 及其要求的引用文件。

1. 标题为 `职业档案｜<名字或昵称>`，后续只更新这一篇。
2. 正文使用 `1.` 到 `8.` 的统一章节编号，对应结论、判断依据、兴趣/能力/岗位、护城河、风险、大师透镜、反脆弱与 ABZ、行动 Roadmap；不混用“一、”“（一）”和 `1.1`。
3. 每节先写 1–2 个独立短段落，每段最多三句、只讲一个中心意思。不要用 `<br/>` 把多段文字塞进同一个 `<p>`。
4. 真正并列的证据、步骤、风险和行动用原生 `<ol><li seq="auto">…</li></ol>` 或 `<ul><li>…</li></ul>`；行动顺序、验证步骤优先编号列表，证据和风险优先项目列表。连续分析保留为段落，避免整篇项目符号化。
5. 岗位、offer、能力账户或阶段计划存在真实行列关系时使用原生表格。长单元格仍拆成短句或列表，不用竖线、斜杠或连续分号模拟表格。
6. 首次完整飞书档案包含 2–3 张已填充画板，至少两张：一张解释核心判断或兴趣到岗位证据链；一张解释长期路径、岗位生态位置或 ABZ。证据充分时可增加护城河、offer 决策树、复利/折旧或反脆弱图。每张图只解释一种关系，紧跟相关章节，不集中堆在文末。
7. 用 `lark-doc` 创建或定位画板，再按 `lark-whiteboard` 写入或更新内容。简单 Mermaid/SVG 画板和复杂画板都必须遵循当前飞书 Skill 的真实调用流程，不凭想象拼命令。续谈优先更新已有 2–3 张画板，不重复创建同义图。
8. 对每个 `board_token` 执行 `whiteboard +export --output-type preview` 或等价预览导出，分别检查非空、文字可读、无明显重叠或截断；不通过就修改并重新预览。不保留空白画板。
9. 写入后执行 `docs +fetch --api-version v2 --detail with-ids` 回读，确认八个章节顺序正确、正文已分成独立段落、该列举的内容使用原生列表、需要对比的内容使用表格、2–3 张画板位于对应章节。
10. 飞书正文和全部画板都成功后才算交付完成。缺少编号/分段、只有纯文字、画板少于两张、存在空白画板或预览不合格时，说明交付未完整并继续修正；工具或授权阻断时，再让用户选择重试/授权或改用 HTML。
11. 选择飞书主档案时只返回飞书链接；选择两种都要时再同时返回 HTML 路径。说明更新了哪些栏目、列表/表格和画板。

## 隐私

`职业档案/` 必须被 `.gitignore` 忽略，不得进入公开仓库或发布包。用户粘贴的文本先转义；禁止嵌入可执行内容和外部追踪资源。
