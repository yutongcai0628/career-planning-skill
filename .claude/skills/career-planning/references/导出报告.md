# 导出报告

当用户说「生成报告」「导出」「做成 HTML / PDF」「存成文档」「写到飞书」时，读取本文件。报告应保留对话中已有的判断、依据、风险和行动，不要另写一篇泛泛的长文。

## 格式路由

- 用户说「HTML / 网页 / 可打印」：生成 HTML。
- 用户说「PDF」：先生成 HTML，再转 PDF 或打印为 PDF。
- 用户说「Markdown / md / 文本版」：生成 Markdown。
- 用户说「飞书 / Lark / 画板」：优先创建飞书文档；没有能力时退回 HTML 或 Markdown，并说明原因。
- 用户未指定格式：给出 HTML、PDF、飞书/Lark、Markdown 四个选项。不要一次生成全部；用户明确说「都要」时，先做 HTML。

## HTML 报告

1. 先读 `assets/报告模板.html` 和 `assets/报告设计哲学.md`。
2. 替换 `{{NAME}}`、`{{DATE}}`、`{{TITLE}}`、`{{SUMMARY}}` 和 `{{CONTENT}}`。
3. 封面只放英文报告名、中文大标题、摘要以及日期/对象。中文使用微软雅黑，英文、数字、缩写和编号使用 Futura。
4. 正文按「结论 → 依据 → 选择路径 → 行动」组织。用 `section`、`.summary-grid`、`.evidence-bars`、`.decision-board`、`.quadrant`、`.timeline` 或 `ol.actions` 中最少的必要组件组织内容。
5. 每份完整报告至少保留一张支持判断的图或表：对比用证据条，路径选择用决策画板，风险取舍用四象限，计划用时间线或行动清单。资料不足时写「证据充分 / 待验证 / 暂无证据」，不要补精确分数。
6. 不要在每一段前面加英文小标签、章节编号、状态徽章或无意义的小字。报告不放头图、图片、外链资源、CDN 或 JavaScript。
7. 用户粘贴的 JD、简历和聊天原文必须先转义 `& < > \" '`；禁止 `script`、`iframe`、事件属性和外链资源。
8. 输出到 `职业档案/报告/职业规划报告-<名字>-<日期>.html`。环境允许时打开；不允许时给出完整路径。模板支持浏览器打印为 PDF。

## PDF

先生成 HTML。首选在浏览器中打印为 PDF；如果当前环境有可靠的 PDF 生成能力，可以直接转换。不要为 PDF 单独维护另一份内容和样式。

## 飞书 / Lark

先判断当前环境是否有飞书文档、云盘或导入能力，或是否已安装并认证 `lark-cli`。没有时退回 HTML/Markdown。

有能力时：

1. 将报告整理为 Markdown，创建或更新飞书文档。
2. 图表需要保留时，当前环境有 `lark-whiteboard` 能力才创建画板。
3. 流程图、时间线和简单路径图优先 Mermaid；四象限、三圈图和复杂关系图可用 SVG/DSL。
4. 画板失败时退回表格或文字结构，不中断文档生成。
5. 将文档链接返回给用户。

## Markdown

生成同一套判断与行动结构。图表改为 Markdown 表格、Mermaid 或一句准确描述。保存到 `职业档案/报告/职业规划报告-<名字>-<日期>.md`。

## 隐私

报告含个人数据，保存到 `职业档案/报告/`。该目录必须被 `.gitignore` 忽略，不能进入公开仓库或发布包。
