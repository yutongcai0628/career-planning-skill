# 导出报告（把规划交付成正式文档）

让规划不只停在对话里，而是交付成一份**能保存、能分享、看起来很专业**的文档。这是把 skill 从"聊天"提升到"咨询产品"的一步。

## 何时提出导出
给完一份完整规划后，主动问一句"要不要我帮你导出成一份正式报告？"；或用户说"生成报告/导出/存成文档/做成 PDF/写到飞书"时立即执行。

用当前环境可用的选择题/表单能力让用户选格式；没有工具时直接在聊天里给 4 个编号选项：
- **HTML 精美报告**（推荐，自带样式、内嵌图表、可直接打印成 PDF）
- **PDF 报告**
- **飞书/Lark 文档**（当前环境有能力才用）
- **Markdown**（朴素、通用）

## 各格式怎么做

### 1. HTML 精美报告（默认、自包含、人人可用）
**视觉基调是 Kinfolk 式杂志编辑排版**：大量留白、衬线大标题、细线分隔、奶油纸色、极克制的暖棕点缀。它应该读起来像一期只为这个人印的杂志，而不是一份数据面板——填充内容时别加彩色块、阴影、渐变或 emoji 堆砌，安静是这个模板的核心。

1. 读取模板 `assets/报告模板.html`。
2. 替换 `{{NAME}}`（用档案里的名字）、`{{DATE}}`、`{{TAGLINE}}`（一句话概括这个人，如"给一个会增长、敢露脸的内容创作者"）、`{{CONTENT}}`。
3. 模板不依赖任何图片；图表由安全内联 SVG 绘制，适合发布到 GitHub / Red Skill，也适合在多数 Agent 里生成。
4. 把 `{{CONTENT}}` 换成本次规划正文，用模板给的结构件写：`section / .pullquote（居中斜体金句，Kinfolk 的招牌，每份报告放 1 处最佳） / .callout（核心洞察） / .insight-grid / .chart-card / .whiteboard / .matrix / .timeline / ol.actions`。免责声明已内置在模板页脚，不必重复写。
   - **HTML 安全**：用户粘贴的 JD、履历、聊天原文等必须先转义 `& < > " '`，不能原样进入 HTML。只允许模型自己生成的结构标签进入模板。
   - 禁止保留 `<script>`、`iframe`、事件属性（如 `onclick`）、外链追踪脚本或用户提供的任意 HTML。
5. **图表**：SVG 粘进 `.chart-card` 或 `.whiteboard`。独立 HTML 里**没有** widget 的 CSS 变量，必须把 `var(--xxx)` 换成模板 `:root` 的固定色：主色/点缀 `#8c6b4f`（暖棕）、文字 `#21201c`、次要 `#6f6a60`、细线 `#e3ded2`、纸色 `#faf8f3`、成功/警告/危险 `#5f7355`/`#a8823e`/`#9c4a3c`。SVG 配色也要跟着这套杂志色走，别用高饱和的图表默认色。
6. 写到 `职业档案/报告/职业规划报告-<名字>-<日期>.html`。如果当前环境允许打开本地文件，就打开它；不允许或不是桌面环境时，把完整路径告诉用户，并说明可用浏览器打开。想要 PDF，可在浏览器打印为 PDF，模板已经为打印优化过。

### 2. PDF 报告
最稳的方式就是**先生成上面的 HTML，再转 PDF**：
- 首选让用户在打开的 HTML 页面里打印为 PDF（macOS 通常是 `Cmd+P`，Windows/Linux 通常是 `Ctrl+P`）。
- 若环境里有 Chrome/Chromium/Edge 的 headless 能力，可命令行转 PDF；路径按当前系统实际改，不要写死 macOS 路径。
- 若当前 Agent 有 PDF 生成/处理能力，也可以用它来生成 PDF。
不要硬造一个脆弱的 PDF 流程——HTML→打印 是最可靠的。

### 3. 飞书/Lark 文档（可选，当前环境有能力才用）
**先判断有没有飞书能力**：可用能力里是否有飞书/Lark 文档、云盘或导入能力。没有就告诉用户"当前环境没有飞书写入能力，我先给你 HTML/Markdown 版"，优雅跳过，别报错。
有的话：
1. 把规划正文整理成 **Markdown**。
2. 用可用的飞书/Lark 文档能力创建文档，或把本地 Markdown/HTML 导入为云文档。
3. **图表优先用飞书画板呈现**：如果当前环境有 `lark-whiteboard` skill/能力，报告里的三圈图、职业路径图、复利 vs 折旧四象限、JD 匹配度图、组织冲击/反脆弱路径图，优先调用 `lark-whiteboard` 写入画板。
   - 使用前按 `lark-whiteboard` 规则读取共享认证说明，确认 `lark-cli` 和 whiteboard CLI 可用。
   - 需要新画板时，先通过飞书文档能力在文档里插入空白 whiteboard，拿到 `board_token`，再交给 `lark-whiteboard` 更新。
   - 流程图、时间线、简单路径图优先用 Mermaid；复杂关系图、四象限、三圈图可用 SVG/DSL 路径。整体更新画板时使用覆盖式更新，避免新旧内容重叠。
   - 画板失败就退回安全内联 SVG、表格或文字结构，并标注"详见 HTML 版图表"，别因为图卡住整个流程。
4. 把生成的文档链接回给用户。

### 4. Markdown（兜底）
直接把规划正文写成 `职业档案/报告/职业规划报告-<名字>-<日期>.md`。图表用一句话描述或附 HTML 版链接。永远能用，零依赖。

## 隐私
报告含个人数据，统一存在 `职业档案/报告/` 下——该目录已被根目录 `.gitignore` 忽略，开源 push 不会泄露。

## 原则
- **内容复用**：报告正文就是你刚在对话里给的规划，别重写一版、别注水，把对话里的判断/分析/建议/行动原样结构化即可。
- **图表带上**：有图的话一定放进报告，这是"高级感"的关键。
- **一次只做一种**：用户选哪种做哪种，做完给路径/链接，别一次全导。
