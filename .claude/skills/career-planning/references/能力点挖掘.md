# 兴趣、能力与职业护城河

所有完整职业规划都要使用本文件。用户越迷茫，越需要从真实经历开始。先找出他愿意重复的任务，再检查已经做出的结果，最后安排一次实际尝试。

兴趣是重要信号，但不自动等于能力或职业机会。职业方向要同时考虑：**兴趣证据、能力证据、价值观、行业需求、人生阶段和现实约束**。

## 一、把兴趣拆成可观察的证据

兴趣由以下元素共同构成：

- **任务**：创造、分析、表达、组织、谈判、服务、研究、打磨等。
- **对象**：人、内容、产品、数据、文化、商业、技术或具体议题。
- **工作方式**：独立/协作、台前/幕后、稳定/变化、深度/速度。
- **反馈来源**：结果增长、作品完成、他人改变、专业认可、商业回报。
- **持续性**：是否会主动回来，是否愿意承受枯燥部分，做完是更有精力还是只想结束。

优先追问具体片段：最近一次忘记时间的任务、没人要求仍主动做的事、被反复求助的事、学得很快的事、最有成就感和最消耗的工作。每个判断至少绑定一条行为或结果，不把“我觉得”直接写成稳定特质。

## 二、从经历走到岗位

兴趣与能力判断要按下面的顺序表达：

**真实经历 → 愿意重复的任务 → 已经证明的能力 → 对应岗位 → 下一次确认**

五步分别回答：

1. **真实经历**：用户具体做过什么，结果和反馈是什么。
2. **愿意重复的任务**：哪类工作做完仍愿意继续，枯燥部分是否也能接受。
3. **已经证明的能力**：哪些能力有作品、结果或他人反馈支持。
4. **对应岗位**：这些任务和能力常出现在哪些岗位，日常工作是什么。
5. **下一次确认**：用一个 2–4 周任务检查匹配，记录投入感、产出和外部反馈。

需要记录状态时，使用下面三类：

| 状态 | 含义 | 最低证据 |
|---|---|---|
| 已确认 | 多次出现，愿意持续投入，现实体验后仍想继续 | 至少两个不同场景的行为证据 |
| 待验证 | 有好奇或一次正反馈，但尚未经历真实工作过程 | 一条线索 + 一个 2–4 周实验 |
| 已排除 | 真实体验后持续消耗，或只喜欢结果不喜欢过程 | 一次具体经历和不匹配原因 |

实际运行顺序：

1. **选取经历**：从学习、工作、项目、副业和日常主动行为中选择 3–5 个片段。
2. **找出重复部分**：记录反复出现的任务、对象、工作方式、反馈来源和消耗点。
3. **写出暂定判断**：只保留 2–3 个兴趣与能力组合，并标明证据状态。
4. **对应岗位**：读取 `行业与岗位地图.md`，给出 1 个主方向和 1–2 个相邻方向。每个方向说明日常任务、匹配依据和主要缺口。
5. **安排实际尝试**：用 2–4 周项目、作品、信息访谈、跟岗或真实任务确认。
6. **根据结果更新**：记录投入感、学习速度、产出质量、外部反馈和继续意愿，再调整判断。

用户每次回来只补本轮最关键证据，不从头做完整问卷。

## 三、把经历提炼成能力

用户描述经历时，通常会说岗位名和做过的事项，例如“做过运营”“写过 PRD”“沟通能力不错”。这些信息还不能直接支持职业选择。能力提炼要继续追问：**你处理了什么问题、作出了什么判断、结果怎样变化、这套做法能否在别处重复。**

先读取 `行业与岗位地图.md` 中的岗位重要性分析。能力不能凭空罗列，要从目标岗位最重要的判断和结果倒推：

**岗位价值 → 关键判断 → 目标能力 → 当前证据 → 训练项目 → 下一份证据**

例如，AI 应用产品的重要价值之一是减少场景误判和无效开发。对应的目标能力包括用户问题判断、模型边界判断和评测迭代。训练动作要落到真实场景、原型和评测记录，不能只安排听课或熟悉工具。

使用下面的表达式：

**能力 = 问题或对象 + 关键判断 + 组织的动作 + 可验证结果**

例如：

- 弱表达：“会整理用户反馈。”
- 初步能力：“能把零散反馈归类并找出高频问题。”
- 可用于求职的能力：“能从零散用户反馈中识别共性问题，结合业务目标排出需求优先级，并用后续反馈检查判断。”

每项能力必须写清四层：

1. **当前证据**：哪段经历、本人负责什么、有什么产物或反馈。
2. **能力边界**：目前只证明到执行、独立判断、系统建设还是组织影响。
3. **下一层能力**：再往上一级需要承担什么更难的问题和结果。
4. **证明方式**：用什么项目、作品、指标或第三方反馈证明升级已经发生。

能力升级通常沿着下面的阶梯发生：

| 层级 | 能力表现 | 判断问题 |
|---|---|---|
| 执行 | 按要求完成明确任务 | 能否稳定交付？ |
| 独立判断 | 面对模糊信息作出取舍 | 为什么先做这个？ |
| 系统建设 | 把一次做法变成流程、工具或标准 | 别人能否复用？ |
| 结果负责 | 对更大范围的业务或用户结果负责 | 结果为什么变化？ |
| 组织影响 | 改变资源分配、团队方法或行业认知 | 能否放大他人的产出？ |

完整规划必须明确输出一组“能力账户”，每组最多 3–5 项：

| 能力 | 当前证据 | 下一层 | 下一份证据 |
|---|---|---|---|
| 用户问题判断 | 参与访谈和反馈整理 | 独立定义问题与优先级 | 一份有取舍依据的需求分析 |
| 评测与迭代 | 尚未证明 | 建立标准并分析失败案例 | 一套评测集和两轮迭代记录 |

最后写一句**能力提炼句**：`能为哪类人或业务，处理什么问题，用什么判断和方法，产生什么结果。` 这句话是当前目标能力，不是终身标签；证据不足的部分要标“待验证”。

### 产品经理常见的能力提炼

产品经理的能力不能只写“沟通、写文档、推进项目”。优先检查：

- **用户问题判断**：能否从反馈、行为和场景中找到真正值得解决的问题。
- **需求与优先级判断**：能否说明做什么、暂时不做什么，以及取舍依据。
- **方案与系统设计**：能否把问题转成流程、功能、规则和边界。
- **实验、评测与数据迭代**：能否提前定义成功，识别失败原因并继续修改。
- **跨团队交付**：能否让算法、工程、设计和运营围绕同一目标完成交付。
- **业务理解**：能否把用户结果、产品指标、成本和商业目标连起来。

### 文科背景进入 AI 时的能力提炼

专业名称不会自动转化为优势。把人文、传播、艺术、语言、社会科学或商业经历拆成可用于 AI 工作的能力，例如：

- 对人和情境的理解 → 用户研究、场景定义和定性证据分析。
- 语言与内容训练 → 知识结构、对话设计、评测标准和产品表达。
- 行业或文化经验 → 判断什么问题值得用 AI、输出是否符合专业情境。
- 项目与沟通经验 → 把模糊需求转成流程，并推动多角色交付。

这些能力要与技术协作素养结合：理解模型边界、数据和评测，能做简单原型，能与工程团队讨论成本、延迟、质量和风险。只会使用某个工具或编写几条提示词，通常还没有形成长期能力。

## 四、把兴趣放进现实条件中

兴趣不能脱离现实，但现实也不能直接压掉兴趣。对候选方向至少检查：

- **岗位与需求**：岗位日常、招聘要求、商业模式和变化速度。先读 `行业与岗位地图.md`，再按当前城市和职级核实近期 JD。无法核实时写明待验证。
- **人生阶段**：把年龄转换为可分析的条件，例如学习窗口、现金流、家庭责任、已有网络和试错成本。不要用“到了某个年龄就不适合”替代证据。
- **进入路径**：用户现有经历能否被招聘方理解，第一块作品或第一个项目从哪里获得。
- **机会成本**：验证这条路会放弃什么，失败后是否可逆。
- **价值排序**：收入、成长、稳定、自由、影响力和生活方式中，当前优先什么。

最后给一个主方向和 1–2 个相邻方向。报告只展开与用户相关的 2–4 个行业。

每个方向要写清：常见职位名称、三项日常任务、匹配依据、主要缺口、14 天验证和一份可提交的作品。用户需要先判断自己是否愿意做岗位日常，再讨论行业光环和公司名。

## 五、从能力点找到职业护城河

职业护城河需要满足三个条件：**能在真实需求中稳定产生结果，别人难以快速复制，离开当前公司后仍能继续积累。** “沟通能力强”或“审美好”只能算自我描述，还需要项目证据。

用下面五项检查：

1. **可重复能力**：是否在不同场景反复做成，并能排除一次运气。
2. **领域认知**：是否理解某类用户、行业、产品或问题，而不只有通用执行。
3. **稀缺组合**：两到三项普通能力叠加后是否形成少见组合，例如“审美 × 用户洞察 × 增长复盘”。
4. **可携带资产**：作品、案例、方法、受众、关系和信誉能否离开平台继续使用。
5. **真实需求与结果**：市场是否愿意为它付钱、给机会或配置资源；结果是否能被说明和验证。

再判断用户目前处于哪一层，并给出下一层的建设任务：

| 层级 | 要回答的问题 | 可验证产物 |
|---|---|---|
| 准入能力 | 能否达到岗位的基本交付标准？ | 基础作品、证书或完整任务 |
| 关键判断 | 面对模糊问题时，能否作出质量更高的取舍？ | 有取舍依据和结果复盘的案例 |
| 可复用系统 | 能否把一次成功变成流程、标准、工具或团队方法？ | 方法文档、评测集、流程或工具 |
| 可携带资产 | 离开公司后还留下什么？ | 作品、案例、受众、信誉和专业关系 |
| 放大杠杆 | 能否通过产品、内容、网络或组织放大影响？ | 被复用的方法、稳定渠道、团队或行业影响 |

准入能力让用户获得机会，关键判断决定长期上限。可复用系统和可携带资产让经验产生复利，放大杠杆扩大影响范围。完整规划要指出当前最薄弱的一层，未来 90 天先补哪项证据，以及未来 3–5 年怎样逐层建设。

完整规划固定输出：

- **当前护城河假设**：一句话写清“为谁，用什么组合能力，解决什么问题”。
- **当前所处层级**：说明已经证明到准入、关键判断、可复用系统、可携带资产或放大杠杆中的哪一层。
- **已有证据**：最多 3 条具体经历或结果。
- **仍缺证据**：什么尚未证明，不能把它包装成优势。
- **迁移范围**：换公司、行业或工具后哪些部分仍有效。
- **建设顺序**：写明未来 90 天补什么证据，1 年形成什么方法或资产，3–5 年建立什么杠杆。

如果证据不足，就写“护城河雏形”或“待验证组合”，不要为了鼓励用户硬造稀缺性。

## 六、行动优先级

- **P1｜现在到 14 天**：会直接改变方向判断、解除关键阻塞或降低重大风险的动作。最多 2 项，先做。
- **P2｜30 天内**：补齐能力证据、作品或市场反馈的动作。最多 2 项，在 P1 启动后推进。
- **P3｜90 天内**：建立长期复利、外部网络、第二曲线或抗风险资产。最多 2 项，不与 P1 抢资源。

每个动作写清截止时间、产物和验收信号。优先级代表顺序与资源分配，不代表 P3 不重要。

## 七、推荐图表

优先使用 `交互与可视化.md` 的兴趣到岗位证据链、护城河分层纸带或职业路径图。兴趣部分按五步顺序连接，不再使用六个平级方框。不使用无依据的精确分数，也不把多个章节都画成圆圈。
