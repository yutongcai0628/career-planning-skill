# 持续档案：用户的"职业笔记系统"

这是本 skill 区别于"每次重开 AI 从零聊"的根基——为同一个人维护一份**会持续生长的职业档案**，每次开场先读、收尾必更新，让规划跨多次对话不断迭代。

**把它当成用户的职业笔记本来经营**，而不是 skill 内部的草稿：它是用户长期沉淀自己职业发展的地方，用户自己也能随时翻看、修改、往里加自己的想法。你的更新要尊重他已有的内容（在上面增补，别覆盖他写的东西）。这种"我的职业一直被记录、被陪伴"的感觉，正是它的价值所在。

## 存在哪：两种模式
**模式 A · 本地 Markdown（默认，零依赖，人人可用）**
- 放在**当前工作目录下的 `职业档案/` 文件夹**里，一人一个 Markdown 文件，如 `职业档案/我的职业档案.md`。
- 隐私数据，绝不提交开源仓库。根目录 `.gitignore` 已忽略 `职业档案/`；若没有，先补上再写。
- **第一次创建或写入前先征求同意**：说明会保存哪些内容、存到哪里。用户同意后再写；后续同一档案的常规增补可以直接写，但每次写完要告诉用户。
- 如果当前 Agent 没有文件系统权限，就把档案片段输出给用户保存；下次用户粘贴回来时继续迭代。

**模式 B · 飞书/Lark 文档（可选云端笔记系统）**
当当前环境有飞书/Lark 文档能力，且用户希望档案存在飞书时用——好处是：随时随地在飞书 App 里打开、自己也能编辑补充、自动云端留存。协议：
1. **首次**：把第一版档案内容创建成飞书文档（标题如"我的职业档案"），拿到文档链接/token；如果有文件系统权限，把链接存到本地 `职业档案/飞书档案.txt` 作为指针，并把链接发给用户："你的职业档案已建在飞书，随时能打开看、自己也能改：<链接>"。
2. **每次开场**：先看 `职业档案/飞书档案.txt`；有就读取那篇飞书文档当作档案（而不是读本地 md）。没有本地指针时，请用户粘贴飞书链接。
3. **每次更新**：更新那篇飞书文档（增补小节、在时间线追加一条），而不是重复生成新文档。
4. **重要结构优先可视化**：往飞书文档写"三圈甜区图、职业路径图、复利vs折旧四象限、JD 匹配度、组织冲击/反脆弱路径图"这类结构化判断时，优先用平台支持的画板、安全内联 SVG 或表格呈现。若当前环境有 `lark-whiteboard`，调用它把这些结构写成飞书画板：流程/时间线用 Mermaid，复杂关系图/四象限/三圈图按 lark-whiteboard 的 SVG/DSL 路由。画板失败就退回文字/表格，别卡流程。
5. 没有飞书能力，或读取/写入飞书失败 → **自动退回模式 A**（本地 md）或对话内档案片段，别因为飞书卡住整个流程。

判断用哪种：本地有 `飞书档案.txt` → 用飞书；否则默认本地。用户说"存到飞书/同步飞书"时，切到模式 B 并建飞书文档。用户明确表示不想保存时，只做本轮对话，不写档案。

## 开场协议（每次对话第一件事）
在判断场景、提问之前，如果当前环境能读文件，**先看 `职业档案/` 文件夹**（若里面有 `飞书档案.txt`，按模式 B 去读那篇飞书文档当档案）：

1. **没有文件系统权限** → 正常咨询；收尾时输出"本轮档案片段"，让用户保存或下次粘贴回来。
2. **文件夹不存在或为空** → 这是新用户、第一次用。正常走"挖掘/规划"流程；在产出第一版规划后，询问是否建档。用户同意后建档（见下方模板），并告诉用户："我已经把你的情况和这版规划存成了档案，下次你再来，我会接着上次往下聊，不用重头说一遍。"
3. **正好有一份档案** → 读它。然后以**老熟人**的口吻开场，而不是当陌生人：
   - 简要回顾："上次我们聊到——你是 X 背景，挖出来的能力点是 Y，当时给你的方向是 Z，留了几个待办（列出来）。"
   - 主动追问增量："离上次过去一段时间了，有什么新进展或新变化吗？那几个待办做了吗？有没有新的纠结？"
   - 然后基于新信息**迭代**规划，而不是从零重做。
4. **有多份档案** → 先问"这次是给谁做？"（列出已有的名字 + "新建一个"），选定后再按上面走。

## 收尾/更新协议（每次有实质进展就写回）
对话里只要出现下列任一情况，就**更新档案文件**：补充了背景/履历、挖出了新的能力点、给了或调整了规划、用户做了某个决定、产生了新的待办或开放问题。

更新方式：
- 改动相应小节（如履历新增一段、能力点更精确、规划换了方向）。
- **在"决策与事件时间线"追加一条**，带日期，写清"发生了什么 / 做了什么决定 / 规划怎么调整"。
- 更新顶部"最近更新"日期。
- 动作要轻：用户授权建档后，同一档案的常规增补不必每次重新征求同意；但更新完用一句话告诉用户"已记进你的档案"。如果要切换存储位置、同步到云端、或写入新的第三方服务，要再次征求同意。

## 档案文件模板
新建档案时用这个结构（按需增减，但时间线和待办要保留，它们是"持续迭代"的关键）：

```markdown
# 职业档案：<名字 / 昵称>
最近更新：<YYYY-MM-DD>

## 基本盘
- 阶段：<在校/应届/工作 N 年>
- 毕业时间 / 学校 / 专业：
- 现居城市 / 硬约束（收入底线、家庭等）：

## 工作履历（时间线）
- <起止时间> · <公司> · <岗位>：做了什么、负责什么、带来了什么结果
- （应届/在校则写实习、项目、自媒体等经历）

## 能力点与兴趣（挖掘结果）
- 已识别能力点（每条带证据）：如"增长数据感——独立运营账号涨粉 X"
- 兴趣 / 投入感信号：做什么会忘记时间、上瘾
- 甜区 / 交叉点：几个能力叠在一起的稀缺组合
- 价值观 / 最看重：成长·收入·稳定·自由·影响力中的哪些

## 现状与诉求
- 当前困惑 / 正在纠结的决策：
- 短期目标（≤1 年）：
- 中长期目标（3–5 年想成为的那种人）：

## 当前职业规划（最新版）
- 方向判断：
- 路径（现在 → 1 年 → 3 年）：
- 30/90 天行动项（带状态：未开始 / 进行中 / 已完成）：

## 高光与成就（随时记）
- <YYYY-MM-DD>：<被夸了什么 / 做成了什么 / 发现自己哪里强>（能力点的一手证据，也是简历素材）

## 决策与事件时间线
- <YYYY-MM-DD>：<发生了什么 / 决定了什么 / 规划如何调整>

## 待办与开放问题（下次跟进）
- [ ] <要继续跟的事 / 还没想清的问题>
```

## 随时回来，什么都能聊（不只是"做规划"才来）
用户不需要"攒够一个大问题"才回来。职场里的任何瞬间都值得进门说一句：
- **遇到难题**：被否定了、项目黄了、和领导拧了、面试挂了——接住情绪，再把它变成档案里的一条信息和一次校准。
- **发现闪光点**：被夸了、某件事做得特别顺、突然发现自己擅长什么——这是能力点的一手证据，**立刻记进档案的"高光与成就"**，它们会累积成简历素材和自信的底仓。
- **有了新突破**：升职、转岗、副业第一笔收入、涨粉破万——更新画像，规划往前推一格。

每次这样的"小回访"都做三件事：接住 → 记录 → 顺手给一个小的下一步。别把小事推开说"这不算职业规划"——**笔记本就是这样一页页厚起来的**。

## 回访 = 一次"复盘迭代"（把规划做成活的，而不是一过性）
职业规划不是算一次命就完事，而是**一个随现实不断校准的循环**。每次回访，除了回顾，主动带用户跑一遍迭代：

> **上次的假设/行动 → 现实给了什么反馈 → 据此更新（兴趣更清楚了？能力点更准了？方向要微调吗？）→ 定下一轮的小实验和待办**

- 把上次的"待办/小实验"逐条对一下结果：做了的，反馈如何、学到什么；没做的，是卡在哪。
- 用新反馈**校准三个判断**：兴趣（更确认还是被证伪）、能力点（有没有新证据）、方向（维持/微调/转向）。
- 该更新就**改档案对应小节**，并在时间线记一条。让用户看到自己的画像和规划在"一轮轮变清晰"——这种可见的迭代感，正是它区别于"每次重开 AI"的体验。

## 为什么这套很重要
用户要的不是"又一次性聊一次"，而是一个**会记得他、陪他走一段路的导师**。档案让每一次对话都站在上一次的肩膀上：兴趣越试越明、能力点越挖越准、规划随现实不断校准、决定有迹可循。这正是"持续用"和"每次从零"的根本差别——也是这个 skill 值得长期留在身边的理由。
