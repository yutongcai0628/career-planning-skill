# 持续档案：用户的"职业笔记系统"

这是本 skill 区别于一次性对话的能力：在用户授权后，为同一个人维护一份会持续更新的职业档案，让规划能根据新情况不断校准。

把它当成用户自己的职业记录，而不是 skill 的内部草稿。用户可以查看、修改和补充；更新时在已有内容上增补，不要覆盖用户原文。它记录的是判断依据、行动、结果和变化，而不是一段段对话摘要。

## 存在哪：两种模式
**模式 A · 本地 Markdown（默认，零依赖，人人可用）**
- 放在**当前工作目录下的 `职业档案/` 文件夹**里，一人一个 Markdown 文件，如 `职业档案/我的职业档案.md`。
- 隐私数据，绝不提交开源仓库。根目录 `.gitignore` 已忽略 `职业档案/`；若没有，先补上再写。
- **第一次创建或写入前先征求同意**：说明会保存哪些内容、存到哪里。用户同意后再写；后续同一档案的常规增补可以直接写，但每次写完要告诉用户。
- 如果当前 Agent 没有文件系统权限，就把档案片段输出给用户保存；下次用户粘贴回来时继续迭代。

**模式 B · 飞书/Lark 文档（可选云端笔记系统）**
当当前环境有飞书/Lark 文档能力，且用户希望档案存在飞书时用——好处是：随时随地在飞书 App 里打开、自己也能编辑补充、自动云端留存。协议：
1. **首次**：把第一版档案内容创建成飞书文档（标题如"我的职业档案"），拿到文档链接/token；如果有文件系统权限，把链接存到本地 `职业档案/飞书档案.txt` 作为指针，并把链接发给用户："你的职业档案已建在飞书，随时能打开看、自己也能改：<链接>"。
2. **每次开场**：先看 `职业档案/飞书档案.txt`；有就读取那篇飞书文档当作档案（而不是读本地 md）。没有本地指针时，请用户粘贴飞书链接。
3. **每次更新**：更新那篇飞书文档（增补小节、在时间线追加一条），而不是重复生成新文档。
4. **在需要时创建画板**：当前环境有 `lark-whiteboard` 且用户希望把结构化判断保存在飞书时，将职业路径、决策树、四象限或 JD 匹配等内容做成飞书画板。流程/时间线用 Mermaid；复杂关系图、四象限、三圈图用 SVG/DSL。整体更新时避免新旧节点重叠。画板失败就退回文字或表格，不中断流程。
5. 没有飞书能力，或读取/写入飞书失败 → 退回模式 A（本地 Markdown）或对话内档案片段。用户需要可浏览版本时，用 `assets/报告模板.html` 生成含图表和行动时间线的 HTML 档案快照，保存到 `职业档案/报告/`。

判断用哪种：本地有 `飞书档案.txt` → 用飞书；否则默认本地。用户说"存到飞书/同步飞书"时，切到模式 B 并建飞书文档。用户明确表示不想保存时，只做本轮对话，不写档案。

## 读取与开场协议
职业档案不是默认读取权限。只有用户说「继续上次」「读取/更新我的职业档案」、提供了档案内容，或此前已授权维护指定档案时，才读取对应档案；不要扫描 `职业档案/` 或其他目录来猜测用户身份。

1. **没有文件系统权限** → 正常咨询；收尾时输出「本轮档案片段」，让用户保存或下次粘贴回来。
2. **指定档案不存在或为空** → 这是第一次建档。先完成本轮分析；产出第一版规划后，询问是否建立档案。用户同意后建档，并告知保存位置和内容范围。
3. **有指定档案** → 读它，并简要回顾已有结论和未完成动作：
   - 回顾：「上次结论是 X，待验证的事项是 Y，目前未完成的是 Z。」
   - 追问：「这段时间发生了什么？哪些行动做了？现在最需要重新判断什么？」
   - 基于新信息更新规划，不从零重复提问。
4. **用户明确提供多份档案供选择** → 问这次要使用哪一份；不要主动枚举文件夹中的档案名称。

## 收尾/更新协议（每次有实质进展就写回）
对话里只要出现下列任一情况，就**更新档案文件**：补充了背景/履历、挖出了新的能力点、给了或调整了规划、用户做了某个决定、产生了新的待办或开放问题。

更新方式：
- 改动相应小节（如履历新增一段、能力点更精确、规划换了方向）。
- **在"决策与事件时间线"追加一条**，带日期，写清"发生了什么 / 做了什么决定 / 规划怎么调整"。
- 更新顶部"最近更新"日期。
- 动作要轻：用户授权建档后，同一档案的常规增补不必每次重新征求同意；但更新完用一句话告诉用户"已记进你的档案"。如果要切换存储位置、同步到云端、或写入新的第三方服务，要再次征求同意。

## 档案文件模板
新建档案时用这个结构（按需增减，但时间线和待办要保留，它们是"持续迭代"的关键）：

```markdown
# 职业档案：<名字 / 昵称>
最近更新：<YYYY-MM-DD>

## 基本盘
- 阶段：<在校/应届/工作 N 年>
- 毕业时间 / 学校 / 专业：
- 现居城市 / 硬约束（收入底线、家庭等）：

## 工作履历（时间线）
- <起止时间> · <公司> · <岗位>：做了什么、负责什么、带来了什么结果
- （应届/在校则写实习、项目、自媒体等经历）

## 能力点与兴趣（挖掘结果）
- 已识别能力点（每条带证据）：如"增长数据感——独立运营账号涨粉 X"
- 兴趣 / 投入感信号：做什么会忘记时间、上瘾
- 甜区 / 交叉点：几个能力叠在一起的稀缺组合
- 价值观 / 最看重：成长·收入·稳定·自由·影响力中的哪些

## 现状与诉求
- 当前困惑 / 正在纠结的决策：
- 短期目标（≤1 年）：
- 中长期目标（3–5 年想成为的那种人）：

## 当前职业规划（最新版）
- 方向判断：
- 路径（现在 → 1 年 → 3 年）：
- 30/90 天行动项（带状态：未开始 / 进行中 / 已完成）：

## 高光与成就（随时记）
- <YYYY-MM-DD>：<被夸了什么 / 做成了什么 / 发现自己哪里强>（能力点的一手证据，也是简历素材）

## 决策与事件时间线
- <YYYY-MM-DD>：<发生了什么 / 决定了什么 / 规划如何调整>

## 待办与开放问题（下次跟进）
- [ ] <要继续跟的事 / 还没想清的问题>
```

## 随时回来补充
用户可以在任何出现新信息的时刻回来，不必等到要做重大选择：
- **遇到问题**：被否定、项目失败、与上级分歧、面试失利。记录事件，判断它改变了哪些假设。
- **发现新证据**：被表扬、完成一项工作很顺、发现自己不擅长什么。把它记入能力证据或工作偏好。
- **出现新变化**：升职、转岗、收入变化、拿到 offer、组织调整。更新约束和下一步计划。

每次回访做三件事：补充事实、更新判断、确定一个下一步。

## 回访 = 一次"复盘迭代"（把规划做成活的，而不是一过性）
职业规划不是算一次命就完事，而是**一个随现实不断校准的循环**。每次回访，除了回顾，主动带用户跑一遍迭代：

> **上次的假设/行动 → 现实给了什么反馈 → 据此更新（兴趣更清楚了？能力点更准了？方向要微调吗？）→ 定下一轮的小实验和待办**

- 把上次的"待办/小实验"逐条对一下结果：做了的，反馈如何、学到什么；没做的，是卡在哪。
- 用新反馈**校准三个判断**：兴趣（更确认还是被证伪）、能力点（有没有新证据）、方向（维持/微调/转向）。
- 该更新就**改档案对应小节**，并在时间线记一条。让用户看到自己的画像和规划在"一轮轮变清晰"——这种可见的迭代感，正是它区别于"每次重开 AI"的体验。

## 这套记录解决什么
职业变化通常不是一次大决定，而是一连串小信息累积后的调整。档案让每次讨论都能引用已有证据：兴趣会被验证或推翻，能力会补充新案例，方向也会随着现实条件变化。这样可以避免每次从零描述背景，也方便回看当时为什么做出某个选择。
