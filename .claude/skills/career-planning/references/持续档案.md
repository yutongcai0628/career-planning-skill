# 持续档案：默认 HTML，飞书可用时选择

职业档案用于展示多次咨询中的事实、判断和行动。完整职业规划默认自动生成或更新本地 HTML；飞书文档能力已连接并授权时，才让用户选择本地 HTML 或飞书文档。飞书不可用时不询问格式，直接交付 HTML。只维护一个主档案，用户明确要求两种都要时再同步双写。

选择 HTML 时，使用**同一个 HTML 文件**，并在同目录维护一个 `.state.json` 私有状态文件。HTML 负责阅读、打印和跨 Agent 交付；状态 JSON 负责可靠地合并局部变化。选择飞书时，持续更新同一篇飞书文档，不额外创建本地 HTML。

只保存会影响职业判断的事实、证据、假设、行动和决策。不要保存逐字对话、身份证号、联系方式、公司机密、客户数据或与职业无关的私人信息。

## 能力边界

- Agent 没有天然的跨会话记忆。持续性来自下次重新读取 HTML 或飞书档案，不要声称“我一直记得”。
- Skill 不能在用户离开后后台监听文件、自动弹窗或定时发消息。定时提醒、飞书通知和表单推送需要另行配置机器人、自动化或日程。
- 用户可以查看、更正、导出、暂停更新或删除档案。删除 HTML 档案时同时处理配套 `.state.json`；删除飞书文档属于外部操作，执行前按当前工具要求确认。切换存储位置、改为双写或新增敏感字段时重新征求同意。

## 首次交付

用户首次提出实质性的个人职业规划问题时，先判断信息是否足够。缺少经历结果、任务偏好或现实约束时，先问 1–3 道选择题；用户回答后形成判断，并在同一轮自动生成报告。不要先交付长篇规划，再追问选择题。

先按当前环境的飞书 CLI/工具说明执行只读授权状态检查。只有文档工具可调用且授权有效时，才算“飞书已连接”；只安装 CLI 或只发现 Skill 名称不算。

飞书已连接：

> 这次报告输出到哪里？A 本地 HTML B 飞书文档。

飞书不可用：

> 不询问格式。完成诊断后默认生成本地 HTML。

用户明确说“不要保存”时只在对话中交付。其他情况下，完成第一版判断后按下面的路由建档：

| 选择 | 行为 |
|---|---|
| 默认本地 HTML | 创建 `职业档案/职业档案.html` 和 `职业档案/职业档案.state.json`，后续持续更新同一组文件。用户明确提供昵称和文件名时可以使用。 |
| 飞书文档 | 创建或更新同一篇 `职业档案｜<名字或昵称>`，不额外生成 HTML。 |
| 两种都要 | 仅在用户明确提出时双写，并保持两边结论与行动一致。 |
| 明确拒绝保存 | 不读取、不写入文件；在对话中交付完整规划。 |

本地不再创建 Markdown 档案。创建前确认 `职业档案/` 被 `.gitignore` 忽略；状态 JSON 与 HTML 都属于隐私数据，不得放进仓库或发布包。生成后返回本地路径，不主动发送到第三方。无文件权限时不要说已保存。

## HTML 固定结构

创建前读取 `assets/报告模板.html` 和 `assets/报告设计哲学.md`。正文使用以下固定 `id`；标题可以自然表达，但 `id` 不要改变：

```html
<section id="conclusion">结论、主路径与决策票据</section>
<section id="evidence">用户证据、事实、推断与待验证项</section>
<section id="interest-map">从真实经历到对应岗位的证据链、岗位生态位置与能力提炼</section>
<section id="moat">职业护城河假设、证据、缺口与可迁移范围</section>
<section id="master-lens">1–2 个大师/标杆透镜及类比边界</section>
<section id="career-path">现在、1 年、3 年路径</section>
<section id="antifragility">组织变化、裁员、行业下行、技能折旧、可携带资产、A/B/Z</section>
<section id="actions">行动 Roadmap、P1/P2/P3 阶段、截止时间、产物、验收信号及状态</section>
<section id="open-questions">下次最多 2–4 个关键问题</section>
<section id="user-notes">用户原文补充；Agent 不删除或改写</section>
<section id="decision-history">按日期追加的决策与事件</section>
```

模板不得使用 JavaScript、外链脚本、图片或 CDN。用户输入必须转义 `& < > " '`；不得写入 `script`、`iframe`、事件属性或外部资源。

涉及具体决策时，`#conclusion` 内必须保留 `.decision-ticket`，记录本轮问题、决策类型、当前建议、一个关键问题、什么时候换方向、先看哪些变化和复盘日期。方向探索则记录优先尝试的方向和停止实验的条件。它是复盘字段，不另增 section。

## 每次续谈

只有当用户提供档案、明确说“继续/更新职业档案”，或本次会话已经创建并正在维护同一文件时才读取。不要扫描目录猜测用户身份。

读取时优先提取：

1. `#conclusion` 的当前建议、关键问题、什么时候换方向、先看哪些变化与复盘日期。
2. `#interest-map` 的岗位生态位置、能力账户，以及 `#moat` 中仍待验证的假设。
3. `#actions` 的未完成动作和结果，先看 P1。
4. `#open-questions` 的待验证问题。
5. `#decision-history` 的最新记录。

开场简短回顾：`上次的主路径是 X，当前在验证 Y，未完成的是 Z。这次发生了什么变化？`

## 动态选择题

选择题从档案中的最新状态生成，避免每次重问题库。只问会改变建议的信息：未验证假设、未完成行动、新 offer/JD/组织变化，以及现金流、城市、家庭时间等硬约束。

当前模式下有可调用的互动工具时，先读取其 schema，再弹出 1–3 题；宿主上限更低时继续减少。没有工具或调用失败时，立即在聊天中给编号选项。允许“其他”“不确定”或补充文字。未回答但仍重要的问题保留在 `#open-questions`，已回答的不要再问。

## 增量更新

以下任一情况都属于实质进展：补充履历或能力证据、明确偏好或约束、出现新 offer/JD/组织变化、完成或放弃行动、调整建议。

有 Python 能力时，以 `.state.json` 为唯一可编辑数据源。第一次生成时将完整字段写入状态文件；以后只准备包含变化字段的补丁 JSON，并通过 `render_report.py --state` 合并。`USER_NOTES` 与 `DECISION_HISTORY` 默认只能追加，防止一次局部更新误删用户原文和历史记录。只有用户明确要求更正或删除这两栏时，才使用 `--allow-protected-replace`。

补丁格式：

```json
{
  "fields": {
    "CURRENT_RECOMMENDATION": "更新后的建议",
    "REVIEW_DATE": "2026-08-20"
  },
  "append": {
    "DECISION_HISTORY": "<p>2026-08-01：完成访谈，主路径保持不变。</p>"
  }
}
```

更新顺序：

1. 定点更新受影响的 section，不整篇重写；先更新 `.decision-ticket` 的建议、换方向条件和复盘点。
2. 更新 `#interest-map`：把新证据放入真实经历、重复任务、已证明能力、对应岗位或下一次确认；同时更新岗位生态位置、能力边界、下一层能力和证明方式。
3. 更新 `#moat`：记录能力组合、作品证据和仍缺的市场验证。
4. 更新 `#master-lens`：只有新信息改变适用框架时才替换。
5. 更新 `#antifragility`：记录风险变化、可携带资产和 A/B/Z。
6. 更新 P1/P2/P3 行动状态与结果，只保留 2–4 个待回答问题。
7. 在 `#decision-history` 追加日期、事实、判断、触发了哪条换方向条件和下一步。
8. 更新页面日期，并告诉用户本次改了哪些栏目。

若宿主无法运行脚本，只能按固定 `id` 定位 section 并精确替换；先复制备份，不得改写 `#user-notes` 的用户原文，也不得删除既有 `#decision-history`。手工更新后重新执行安全检查。

## 飞书文档

用户选择飞书文档，或明确说“保存到飞书”时，先读取当前环境的 `lark-doc` 或等价飞书文档指引，再创建或更新同一篇飞书文档。固定栏目与 HTML 结构语义一致；飞书成功后返回同一链接，不为每次咨询新建文档，也不同时生成 HTML。

若调用失败、授权过期或目标文档不可写，说明本轮尚未保存，并让用户选择改用本地 HTML 或只在对话中交付。不要自动回退到 HTML。用户明确要求两种都要时，先分别确认本地文件和飞书写入均成功，再说明同步结果。

需要结构化表达且存在 `lark-whiteboard` 能力时，一个正在进行的决策最多维护一张主画板：兴趣探索用“真实经历 → 重复任务 → 已证明能力 → 对应岗位 → 下一次确认”，护城河用能力组合公式，路径用流程图，offer/去留用决策树，反脆弱用“冲击 → 可迁移能力 → 可携带资产 → B/Z 方案”。选择最能解释本轮结论的一种，不把所有图塞进同一张画板。画板不保存个人事实，失败时退回文档表格。

## 更新的意义

每次回访只做三件事：补充事实、校准判断、确定下一步。选定的 HTML 或飞书主档案会逐渐积累用户的能力证据、决策理由、作品资产和风险准备，这才是它比一次聊天更有价值的地方。
