# 岗位分析（手里有具体岗位 / JD）

适用对象：用户贴出一段 JD（职位描述），或在纠结某个具体 offer / 职位 / 入职 / 离职选择，想知道"这个岗位适不适合我、该不该去、该不该入职、该不该离职、去了怎么发展"。

**前提**：要给出有用的分析，你需要知道用户自己的情况（阶段、能力点、目标）。如果用户只甩了 JD 没说自己，先按 `../SKILL.md` 的"地基信息"补 2–4 个关键问题——尤其是他的能力点和他想要什么。不了解这个人，任何匹配度分析都是瞎猜。

分析按下面五步走，最后汇成结论。**第二步的匹配度，用 `交互与可视化.md` 的图 7（JD 匹配度图）画出来**——把每条要求标成已具备/可补齐/硬伤缺口，让"适不适合"一目了然。

如果用户问的是"该不该离职/辞职"，不要只分析现岗位坏不坏，要同时判断：
- **离开的理由是否真实且足够强**：是成长停滞、价值错配、健康风险、组织变化、薪资倒挂，还是一时情绪。
- **留下的成本**：继续待 6–12 个月，会为能力账户存钱，还是只是在消耗时间和信心？
- **离开的准备度**：现金流、下一步方向、作品/简历、面试管道、家庭约束是否撑得住。
- **可逆性**：先内部转岗、谈条件、骑驴找马，还是必须立即离开。

如果用户问的是"该不该入职/接受 offer"，不要只看薪资和 title，要同时判断：
- **这份 offer 是否通向他想成为的人**：岗位能不能积累可迁移能力和可携带资产。
- **真实工作内容**：JD、面试反馈、汇报线、团队阶段是否一致，有没有明显红旗。
- **机会成本**：接受它会错过什么，不接受它又损失什么。
- **入职后的 90 天打法**：如果建议去，必须给出入职后怎么快速站稳、验证判断、避免踩坑。

## 第一步：拆解这份 JD（读出字面之外的东西）
JD 是公司的"愿望清单"，要读出它背后真正想要的：
- **硬性要求 vs 加分项**：哪些是门槛（不满足直接出局），哪些是"最好有"。别被一长串要求吓退——通常满足 60–70% 就可以投。
- **这个岗位真正要解决什么问题**：透过职责看它存在的目的。是开疆拓土（0→1）、还是维持优化（1→N）、还是填坑救火？
- **隐含信号**：要求里反复出现的词暴露团队的真实偏好（"抗压""从 0 搭建""跨部门协调"各自意味着很不一样的工作状态）。
- **这个岗位在公司里的位置**：是核心业务还是边缘部门？是花钱的成本中心还是赚钱的利润中心？这决定了资源、话语权和成长空间。

## 第二步：匹配度分析（你 × JD）
把用户的能力点逐条对到 JD 上，分三类讲清楚：
- **已具备**：哪些要求他正好擅长——这是他的卖点，面试该重点讲。
- **可补齐的缺口**：缺、但能在合理时间内补上的。给出怎么补。
- **硬伤缺口**：短期补不上、又是核心要求的——如果有，诚实说出来，并判断是否致命。

匹配度不必算成百分比，但要给一个清晰的定性结论：**很合适 / 够得着但要补课 / 有明显错配。**

## 第三步：这个岗位能给你什么（最重要的一步）
匹配只说明"能不能进"，更关键的是"值不值得去"。回到能力账户和复利思维（见 `中期规划.md`）：
- **它在为你的核心竞争力存钱吗？** 这段经历能不能加厚你想要的那个壁垒、补上目标画像里缺的拼图？
- **三年后这段经历值钱吗？** 是会复利的能力，还是会折旧的执行？
- **成长性**：能接触到核心业务、好的人、真问题吗？还是大概率沦为螺丝钉？

一个匹配度很高但只是横向重复、不带来新能力的岗位，可能反而不该去；一个要补点课、但能让你跨上一个台阶的岗位，往往更值。

## 第四步：扫红旗（风险）
主动指出 JD 和情境里的警示信号：
- 职责写得又杂又散 → 可能没想清楚要招什么人 / 一个人当几个人用。
- "需要高度抗压""能接受弹性工作时间" → 留意工作强度。
- 汇报线和团队稳定性、业务/行业的前景、岗位是新设还是有人离职留下的坑。
- 头衔与实际职责不符（给个大 title 但干的是执行）。

## 第五步：结论与去了之后的规划
最后收成一个明确判断，套用 `../SKILL.md` 的报告模板，并务必包含：
- **该不该去的明确倾向**（别和稀泥），以及什么条件下结论会反转。
- **如果去**：进去后头一年该重点攒什么、怎么避免沦为螺丝钉、这一步在你整条路径里扮演什么角色、下一步可能通向哪里。
- **如果不去 / 还要谈**：面试或谈 offer 时该问清楚的关键问题（团队、业务、成长空间），帮他把信息补全再做决定。

## 多 offer / 多机会抉择（A vs B vs 现状）
当用户手里有**两个及以上**选择要二选一（两个好 offer、大厂还是创业、跳还是留），别只盯薪资，按这个走：

1. **先把每个选项各自做一遍上面的"这个岗位能给你什么"**（第三步）——抉择的核心从来不是"哪个现在好"，而是"哪个更接近你想成为的人、更在为你的核心竞争力存钱"。
2. **建一张加权对比表**：列出对你当前阶段真正重要的维度，按权重打分。常见维度——成长/能力账户、平台与人、业务前景、可逆性、薪资、生活与通勤、个人价值/意义。**关键是权重要贴合用户此刻的诉求**（看重成长的人，"成长"权重就该压过"薪资"），而不是给一张人人通用的表。
3. **大厂 vs 创业**这类经典抉择，把 `中期规划.md` 的 A 节框架落到这两个具体选项上。
4. **用思维透镜辅助决断**（见 `标杆与思维透镜.md`）：
   - **后悔最小化**：三年后回头，哪个选择你更不会后悔？
   - **反过来想**：哪个选项最可能让你三年后后悔/掉价？先排除它。
   - **可逆性**：哪个错了更容易回头？不确定时，优先选可逆的、信息更多的那个。
5. **给明确倾向**，别甩一张表让用户自己算——说清你更推荐哪个、为什么、什么情况下选另一个。
6. **配图**：用 `交互与可视化.md` 图 5 的变体画一张**多 offer 对比图**（按维度并排、高亮推荐项），让取舍一目了然。
