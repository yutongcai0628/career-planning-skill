# 职场规划导师 skill — 编辑指南（README）

> 这份 README 是给**人**看的，帮你快速找到"想改某个行为该动哪个文件"。
> Agent 运行时通常**不读**这个文件，它读的是 `SKILL.md` 和按需加载的 `references/`。

## 这个 skill 是干什么的
扮演一位职业规划导师，帮用户做职场规划。四个核心场景：
1. **能力点挖掘**（刚入职场 / 迷茫，从兴趣挖到能力）
2. **成长进阶**（大厂vs创业 / 核心竞争力 / 突破天花板 / 个人价值）
3. **岗位 / Offer 抉择**（单 JD 适配 + 多 offer 对比）
4. **职业反脆弱**（组织变化 / 裁员 / 行业下行 / 找能终身做的事）

让它区别于普通聊天的三样东西：① 用**选择题**挖掘，代替让用户写小作文（有表单工具就弹窗，没有就聊天编号）；② 用**图表**把结论画出来（widget / Mermaid / SVG / Markdown 表格都可）；③ **持续档案**让它记住每个用户、越用越准。语气上有硬规则：说话要有人味儿、去 AI 腔、靠提问引导思考、盯执行，每份规划结尾必须带免责声明。

### 持续档案（跨对话记忆 · 职业笔记系统）
本 skill 会为每个用户维护一份会持续生长的职业档案，每次开场先读、收尾更新，从而"越用越懂你"。两种存储模式：
- **本地 Markdown（默认）**：经用户同意后，存在当前目录 `职业档案/` 文件夹，零依赖、人人可用。
- **飞书文档（可选）**：当前 Agent 有飞书/Lark 能力时，档案可存成飞书云端文档，用户随时在飞书 App 里翻看、自己也能编辑。靠本地 `职业档案/飞书档案.txt` 记住文档链接。
- 隐私：`职业档案/` 已被根目录 `.gitignore` 忽略，**开源 push 不泄露**；skill 本体不含任何人的数据。

`SKILL.md` 是入口，它在合适的时候用 `references/xxx.md` 这样的指针把对应文件"按需加载"进来——所以改方法论去对应 reference，改整体行为去 SKILL.md。

## 改之前要知道的几件事

- **`description`（SKILL.md 第 3 行）决定触发**。Claude Code、Codex 等支持 skill 元数据的平台会靠它判断"用户这句话要不要用本 skill"。想让它在更多/更少场景触发，就改这里的关键词。
- **选择题要能降级**：有选择题工具时一次最多 4 题、每题最多 4 个选项；没有工具时用聊天编号选项（详见 `交互与可视化.md`）。
- **图表要能降级**：widget 里可用 CSS 变量；独立 HTML/通用 Agent 里改用固定色、Mermaid 或 Markdown 表格。
- 改完**直接生效**，不用重启——下次触发就是新版本。

## 怎么测试改动有没有效果
在目标 Agent 里说一句会触发的话，看它是否能在没有专用工具的情况下完成：读/建档前先征求同意、用编号选择题问关键信息、至少给一张可降级图表、结尾带免责声明。

建议用这些测试句覆盖主要触发：
- "帮我做职业规划。"
- "我该不该离职？"
- "我要不要入职这家公司？"
- "这是 JD，你看我适不适合。"
- "我怕被裁，行业也在下行，怎么办？"
- "把这次规划导出成 HTML / Markdown / 飞书文档。"

## 发布前检查

- `SKILL.md` 的 `description` 覆盖职业规划、入职、离职、offer、JD、转行、被裁、组织变化、行业下行。
- 不写死 Claude Code、Codex、飞书或某个专用工具；所有外部能力都要能降级。
- HTML 报告不依赖外部图片、脚本或 CDN；用户输入必须转义。
- 实时数据不编造，不能核实时明确说明。
- `职业档案/`、`.DS_Store`、`.claude/settings.local.json`、压缩包、本地测试报告不能进发布包。
- 用 `git status --ignored --short` 和 `git diff --check` 过一遍。
