# 职业规划导师

把模糊的职业问题，转成有依据的判断和下一步行动。

这是一个面向 Claude Code、Codex、Kimi、Cursor Agent 及其他支持文件型规则的 Agent 的职业规划 Skill。它适合处理职业方向、入职与离职、offer、JD、转行、晋升、组织变化和行业下行等问题。

它不是替用户做决定，也不把职业规划简化成一份性格测试。它的目标是：基于用户真实经历、当前约束和可验证信息，给出清楚的判断、风险和可执行的下一步。

## 你可以拿它解决什么

- 「我现在遇到一个问题：领导让我转到另一个业务线，我该去吗？」
- 「我该不该离职？留下和离开的代价分别是什么？」
- 「我要不要入职这家公司？这份 offer 对我下一步有没有帮助？」
- 「这是 JD 和我的简历，这个岗位适合我吗？」
- 「我不知道自己适合做什么，怎么从已有经历里找到方向？」
- 「我工作三年了，下一步该积累什么能力？」
- 「公司在调整、行业在下行，我该怎样降低职业风险？」
- 「继续我的职业档案：我这周遇到了一个新问题。」

你不需要一次性交代完整背景。可以先说问题，也可以直接贴 JD、简历片段、offer 条款、薪资结构、面试反馈或你自己整理的数据。Skill 会补问那些会改变结论的问题。

## 它和普通聊天有什么不同

普通聊天可以给建议，但常常缺少决策过程。这套 Skill 对每次完整咨询有几项固定要求：

| 环节 | Skill 的做法 |
|---|---|
| 明确问题 | 先确认这次到底要决定什么，而不是直接抛一套通用职业建议。 |
| 收集证据 | 把用户经历、现实约束、公开事实和推断分开；缺信息时只追问关键问题。 |
| 给出判断 | 明确推荐哪个方向、为什么，以及哪些信息出现后结论会改变。 |
| 变成行动 | 输出 30/90 天动作，写清时间、产物或验收信号。 |
| 留下记录 | 用户授权后，把结论、行动和新事件写进职业档案，下一次可在原有信息上更新。 |

它也会根据问题选择合适的图表或结构化表，例如 offer 对比、能力证据图、路径图、JD 匹配表、职业风险四象限。图表是为了把判断说清，不是为了装饰报告。

## 怎么开始与继续

第一次使用，直接像下面这样说：

```text
帮我做职业规划。我现在做产品运营 2 年，想转产品经理，但担心收入下降。

我该不该离职？我在现在公司待了 18 个月，手里有一个新 offer。

这是我的简历和 JD，帮我判断是否值得投递。
```

以后遇到新情况，可以随时回来补充：

```text
继续我的职业档案：我现在遇到的问题是组织要调整，我可能会被转岗。

更新我的职业规划：我试了上次建议的项目，发现自己更喜欢客户研究，不喜欢纯投放。

我有一个新 offer。按我们上次的目标，帮我重新判断要不要去。
```

职业档案不是默认读取的。只有用户明确要求继续、提供档案内容，或已经同意维护指定档案时，Skill 才会读取或更新它；没有文件权限时，会输出可复制的档案片段。

## 你会拿到什么

默认先在对话中给出简洁的规划或决策建议。需要保存、分享或复盘时，可以指定格式：

- `Markdown`：适合复制到笔记软件或长期维护。
- `HTML`：适合浏览和打印，包含结论、图表、决策画板和行动时间线。
- `PDF`：先生成 HTML，再导出或打印为 PDF。
- `飞书 / Lark`：当前环境有飞书能力或已配置 `lark-cli` 时，可创建或更新飞书文档；有 `lark-whiteboard` 时，路径图、决策树和四象限可同步为画板。

没有特定工具时，Skill 会退回 Markdown、Mermaid、SVG 或表格，不会因为缺少某个平台能力而中断。

匿名 HTML 预览见 [职业决策报告示例](examples/职业决策报告示例.html)。

## 数据与边界

- 可以基于用户提供的简历、JD、offer、薪资、公司信息和个人约束分析，并明确这些信息来自用户。
- 对公司经营、融资、裁员、薪资、法规、行业数据等动态信息：有可靠搜索能力时查公开来源；无法核实时会说明不确定性，不补造数字或新闻。
- 不要粘贴身份证号、电话、住址、公司机密、客户数据或未公开业务信息。
- 输出是职业规划与决策支持，不构成法律、劳动争议、签证、投资、税务、医疗或心理健康意见。重要决定应由用户结合完整信息作出，必要时咨询专业人士。

## 安装

本仓库的 Skill 目录是：

```text
.claude/skills/career-planning/
```

### Claude Code

放到项目内：

```text
你的项目/.claude/skills/career-planning/
```

或复制到全局目录：

```bash
cp -r .claude/skills/career-planning ~/.claude/skills/
```

### Codex

```bash
mkdir -p ~/.codex/skills
cp -r .claude/skills/career-planning ~/.codex/skills/
```

之后可说：`用 $career-planning 帮我判断要不要离职。`

### Cursor

Cursor 使用项目规则，而不是 Claude 的 Skills 目录。将适配文件复制到打开的项目中，并同时保留项目根目录下的 `.claude/skills/career-planning/`：

```bash
mkdir -p .cursor/rules
cp adapters/cursor/career-planning.mdc .cursor/rules/career-planning.mdc
```

这个规则会在相关对话中引导 Cursor Agent 读取同一份 `SKILL.md`，所以方法论只维护一处。它使用当前推荐的 `.cursor/rules/*.mdc` 项目规则格式；不要新建旧版 `.cursorrules`。

### Kimi 与其他 Agent

如果平台支持导入 Skill、规则文件或知识库，导入 `.claude/skills/career-planning/` 整个目录，并保持 `references/` 与 `assets/` 的相对路径可访问。

不同平台对自动触发的支持并不一致。支持读取 `SKILL.md` 元数据的平台会根据描述匹配职业规划、离职、入职、offer、JD、转行等请求；其他平台请在规则中引用 `SKILL.md`，或让用户明确说「使用 career-planning skill」。
